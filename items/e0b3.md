Agents' scratch repos keep showing up in Jeff's mull serve: any mull command run in a repo with a mull branch registers it in ~/.config/mull/repos for good, and serve then lists it and refreshes on every write to it. Workers ran plain mull commands in scratch demo repos (under the system temp dir), so they landed in Jeff's project list. Jeff, 2026-11-23: this must stop without relying on agents to remember.

1. Never auto-register a repository whose main worktree is under the system temp dir: os.TempDir() / $TMPDIR, /tmp, /private/tmp, /var/folders (compare resolved paths, so /tmp and /private/tmp both match). Explicit registration isn't affected.
2. `mull unregister [path]` (default: the current repo) removes a path from the registry. mull serve drops it on its next registry read.
3. Tests: a repo under the temp dir is never registered by a command run in it; a normal repo still is; unregister removes it. Tests must use an isolated XDG_CONFIG_HOME, as now.

Also found when the bench seed (.dev/bench/large) and a deleted scratch repo showed up in mull serve. Not in scope: dropping registered paths that no longer exist (keep it in mind; say in the design notes whether it's worth doing).
