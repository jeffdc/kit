In mull guide agents and mull guide supervisor: when an item gets its own worktree, branch <id>-<name> from the plan's target and set it up as the plan's rules say; once the item is accepted and its work is in the target, the supervisor removes the worktree and its merged branch (git worktree remove, git branch -d). mull itself never creates or removes worktrees (decided on c6c0).

Update docs/design.md, the guides (internal/guide) and mull guide json wherever behaviour or output changes. The plan's doc (mull plan doc supervised-work) has the whole picture and what stays out of mull.
