The human's words: the tree state seems to always open on the same items when I refresh it. it is unclear to me the logic behind it. need to decide how it should work and understand what it does today.

What it does today (tree.js): the set of open rows is kept in the browser's localStorage (mull.tree.v1) and restored on load. Opening a sheet expands the tree down to its row (expandFor) and saves that, and nothing ever collapses a row but a click on its chevron. So the open set is the trail of every sheet visited plus every row opened by hand, per browser.

To decide: what opens on load (only the current sheet's path? the projects with something that needs you or that changed? the last session's state?), whether visiting a sheet should leave its path open, and how it fits with 18d6 (a fully done branch opens collapsed at its highest done node).
