Jeff's words, 2026-11-12: Idea for the UI in the list of code files changes, it would be sweet if I could click on the file and load it in an editor of my choice (configured I suppose)

Where: the review packet's "Files by layer" table on an item's sheet (mull/internal/serve/web/item.js, around line 115), drawn from the done report's changes (status, path, added, removed per file). Today each path is plain `<code>`.

Things to settle when it's picked up:
- Configured per machine, like mull name: in ~/.config/mull/, never on the mull branch, since each person who works on a repo has their own editor.
- Two ways to open: a URL scheme the browser hands to the editor (vscode://file/<abs>:<line>, cursor://, zed://, idea://open?file=…), which needs no server change; or the server running a configured command (e.g. `zed {path}` or `open -a …`), which works for any editor but is mull serve launching a process, so it must be a narrow endpoint that takes only paths inside a registered repository.
- Which checkout: the item's worktree may be gone once the work is done, so open the path in the repository's main worktree, and say so when the file there no longer matches what the report describes.
- Deleted files (status D) have nothing to open; renamed files open at the new path.
- Not a write under DESIGN.md's Two Kinds of Action Rule (it saves nothing to mull), and not a copy either: a plain link-like action, so DESIGN.md needs a line on how it looks.
- Maybe the same link wherever a file path shows (done-report text, doc margins).
