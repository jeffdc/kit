Every mull command registers its repository (cmd/root.go, registry.Register). An agent that runs mull in mull/.dev/demo to inspect or seed the demo without XDG_CONFIG_HOME=.dev/cfg adds the scratch demo to ~/.config/mull/repos, so Jeff's own mull serve lists it (and lists it unreadable once the worktree goes). It happened in a0e3: the demo at .claude/worktrees/agent-adaf6fbf48f58145a/mull/.dev/demo is now in Jeff's registry and seen.json. There is no command to unregister a repository, and agents' sandboxes may refuse to set XDG_CONFIG_HOME. Options: skip registering paths under a .dev/ dir, add mull serve --forget <path>, or have the guides warn.
