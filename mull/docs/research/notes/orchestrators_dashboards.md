# Agent orchestrators, fleet managers, and multi-agent dashboards for AI coding agents (2025–2026)

Research date: 2026-11-09. Scoring is against the target tool's three pillars: TRUTH (status from evidence such as git, merges, CI and tests, plus drift detection), ATTENTION (a queue of agent decisions waiting for ratification and questions blocking work), and COVERAGE (in-scope items nobody is touching, deferred items, and findings that were never tracked).

## Q1. Which tools exist?

### Takeaway
The space is crowded and changes fast. Five groups stand out: (a) local desktop or TUI "worktree managers" (Conductor, Crystal→Nimbalyst, claude-squad, Superset/Paradev, Emdash, Vibe Kanban, Sculptor); (b) vendor-native multi-session views (Claude Code agent view, agent teams, Projects; the Codex app; Cursor 3 Agents Window; GitHub Agent HQ/mission control); (c) cloud async agents with session lists (Devin/Managed Devins, Jules, Codex cloud, Warp Oz, Amp orbs, OpenHands, Factory); (d) role-based "agent town" orchestrators (Gas Town on Beads, Multica, Imbue mngr); and (e) thin monitoring dashboards (ccdeck, Lazyagent, recon, agent-view). Several have already died or been absorbed: Terragon (Feb 2026), Vibe Kanban's company Bloop (Apr 2026), Crystal (Feb 2026), Jules (winding down Dec 2026), and HumanLayer (acquired by Factory in Nov 2026).

### Cited Findings

**Local worktree managers / desktop cockpits**
- **Conductor** (Melty Labs, YC S24): a Mac-only app that runs Claude Code, Codex, Cursor and OpenCode in parallel git worktrees. Each task gets its own workspace, branch, terminal, diff and review path, and work flows to a PR, then merge, then archive. Its docs list a "Checks" reference page and a Diff viewer. — [Conductor docs](https://www.conductor.build/docs/); [continuumcode guide](https://continuumcode.ai/guides/what-is-conductor/)
- Conductor is built on the Claude Agent SDK and Tauri. Worktrees live under `~/conductor/workspaces/<repo>/<workspace>`, and setup scripts copy git-ignored files. It is Mac-only and requires GitHub. — [continuumcode guide](https://continuumcode.ai/guides/what-is-conductor/)
- **Crystal** (Stravu): an Electron app running Claude Code and Codex sessions, each in its own git worktree. It was announced in June 2025. The final release, v0.3.5 (2026-02-26), says "it will not be updated in the future" and recommends migrating to Nimbalyst. — [Crystal v0.3.5 release](https://github.com/stravu/crystal/releases/tag/v0.3.5); [Nimbalyst: Crystal successor](https://nimbalyst.com/crystal/)
- **Nimbalyst** (Stravu, the Crystal successor): adds a session kanban, visual editors for markdown, mockups and diagrams, inline diff review, built-in task tracking, and an iOS companion app. It uses the same Claude Code CLI underneath. — [nimbalyst.com/crystal](https://nimbalyst.com/crystal/); [rywalker research](https://rywalker.com/research/nimbalyst)
- **claude-squad** (smtg-ai): a Go TUI that uses tmux for one session per agent and git worktrees for one branch per session. It manages Claude Code, Codex, OpenCode and Amp, and installs via Homebrew as `cs`. — [GitHub](https://github.com/smtg-ai/claude-squad)
- **Vibe Kanban** (BloopAI): a kanban board in which each card runs a coding agent in its own worktree, with branch, terminal and dev server. It supports inline diff comments sent back to the agent, AI-written PR descriptions, and a built-in browser preview, and works with 10+ agents. — [GitHub](https://github.com/BloopAI/vibe-kanban)
- **Sculptor** (Imbue): a desktop app that runs parallel Claude Code agents in Docker containers instead of worktrees. It has "Pairing Mode" (two-way sync via Mutagen into your IDE), merge-conflict help, conversation forking, and "instruction audits". It was rebuilt and relaunched around 2025-10-01. — [Imbue announcement](https://imbue.com/blog/sculptor-announce); [Sculptor page](https://imbue.com/sculptor/)
- **Superset → Paradev**: a macOS app for orchestrating CLI agents in worktrees under `~/.superset/worktrees/`, with automations, remote hosts and an iOS app. As of Nov 2026 the README reads "Paradev (formerly Superset)", and desktop-v2.0.5 shipped 2026-11-05. — [munderdiffl.in, Paradev alternatives](https://munderdiffl.in/blog/paradev-alternatives/); [superset.sh compare](https://superset.sh/compare/superset-vs-emdash)
- **Emdash** (YC W26): a cross-platform Electron app that supported 34 agents (Aug 2026). It offers a worktree pool, remote SSH projects, and issue-tracker import. Emdash Classic v1.2.11 shipped 2026-11-06, and new development has moved to a cloud "Emdash 2.0" for teams. — [munderdiffl.in](https://munderdiffl.in/blog/paradev-alternatives/); [emdash blog](https://emdash.com/blog/what-is-emdash)
- Other names that appear in roundups but were not investigated: Orca, Pane, Agentastic, Traycer, Hermes IDE, Parallel Code, CodeAgentSwarm, Worktrunk, amux. — [munderdiffl.in](https://munderdiffl.in/blog/paradev-alternatives/); [dev.to comparison](https://dev.to/gabrielanhaia/conductor-vs-claude-squad-vs-hermes-ide-3-worktree-managers-for-parallel-agents-4818); [byteiota Worktrunk](https://byteiota.com/worktrunk-run-5-ai-coding-agents-in-parallel-without-merge-hell)

**Vendor-native (Anthropic / Claude Code)**
- **Subagents** run inside one session. **Agent teams** (experimental, off by default, behind `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`) have a lead plus teammates, a shared task list (pending / in progress / completed, with dependencies shown as blocked), a file-based mailbox, and hooks named `TeammateIdle`, `TaskCreated` and `TaskCompleted` that can veto completion with exit code 2. — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams)
- Agent teams launched as a research preview in Feb 2026 (v2.1.32). — [alexop.dev](https://alexop.dev/posts/from-tasks-to-swarms-agent-teams-in-claude-code/)
- **Agent view** (`claude agents`, research preview, launched 2026-05-11, v2.1.139+): one screen for background sessions grouped as Pinned / Ready for review / Needs input / Working / Completed. `claude agents --json` exposes `state` (working, blocked, done, failed, stopped) and `waitingFor` (permission prompt, input needed, sandbox request, worker request, dialog open). — [Claude Code docs: agent view](https://code.claude.com/docs/en/agent-view); [pasqualepillitteri.it](https://pasqualepillitteri.it/en/news/2384/claude-code-agent-view-cli-dashboard-sessions-2026)
- **Projects** (redesigned, beta from 2026-09-17): one long-lived coordinator conversation that starts parallel "threads", which are cloud sessions or local ones via Remote Control. An Overview pane groups threads as Ready for review / Waiting on you / Working / Landing / Idle / Resolved. It has project memory files (MEMORY.md) for "requirements, decisions, and pitfalls", plus project instructions up to 16,000 characters. — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects); [MarkTechPost](https://www.marktechpost.com/2026/09/17/anthropic-launches-claude-code-projects-in-beta-parallel-cloud-sessions-that-keep-running-after-you-close-your-laptop/)
- Claude Code also offers cross-session messaging, which lets Claude list and message your other sessions on the same machine, another machine, or in the cloud. — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams); [aicatchup](https://aicatchup.com/news/claude-code-projects-parallel-cloud-sessions)

**Vendor-native (others)**
- **OpenAI Codex app** (macOS, 2026-02-02; Windows 2026-03-04 per OpenAI): manages multiple agents in threads grouped by project, with built-in worktrees, diff comments, PR creation and scheduled automations. Wikipedia reports it was merged into the ChatGPT desktop app on 2026-07-09. — [OpenAI: Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/); [The New Stack](https://thenewstack.io/openais-codex-desktop-app-is-all-about-managing-agents/); [Wikipedia](https://en.wikipedia.org/wiki/OpenAI_Codex_(AI_agent))
- **Cursor 3 "Glass"** (2026-04-02): replaced Composer with an Agents Window that runs agents in parallel across local workspaces, worktrees, cloud VMs and SSH. Background/cloud agents run on AWS VMs. Sources cite a practical limit of 8 concurrent local worktrees. These are mostly third-party sources. — [DEV: Cursor 3 Glass](https://dev.to/gabrielanhaia/cursor-3-glass-replaced-composer-with-an-agents-window-1pcg); [agentpatterns.ai](https://www.agentpatterns.ai/tools/cursor/agents-window/)
- **GitHub Agent HQ / mission control** (announced 2025-10-28 at Universe): one place to assign, steer and track Copilot and third-party agents (Anthropic, OpenAI, Google, Cognition, xAI) across github.com, VS Code, mobile and CLI. It shows real-time session logs, allows pause, refine or restart, and links to the resulting PRs. The Dec 2025 guide says to review three parts: "session logs, files changed, and checks". Steering does not yet work for third-party agents. — [GitHub blog: mission control](https://github.blog/ai-and-ml/github-copilot/how-to-orchestrate-agents-using-mission-control/); [The New Stack](https://thenewstack.io/github-embraces-the-coding-agent-competition-with-agent-hq/); [VentureBeat](https://venturebeat.com/ai/githubs-agent-hq-aims-to-solve-enterprises-biggest-ai-coding-problem-too)

**Cloud async agents**
- **Devin**: parallel sessions arrived in Feb 2026 and "Managed Devins" in Mar 2026. In Managed Devins a coordinator session splits a task among child sessions, each in its own VM. The coordinator can message, terminate, tag and schedule sessions. An "Auto-approve child sessions" toggle lets the human review each batch before launch. — [Devin docs: advanced capabilities](https://docs.devin.ai/work-with-devin/advanced-capabilities); [agentmarketcap](https://agentmarketcap.ai/blog/2026/04/10/devin-parallel-sessions-multi-agent-concurrency)
- **Google Jules**: `--parallel` runs up to 5 attempts at one prompt. A Gemini CLI extension fans out GitHub issues in parallel. On 2026-10-29 Google announced Jules will wind down on 2026-12-31, with sessions going read-only after 2026-11-11. — [Jules changelog](https://jules.google/docs/changelog/); [Google Cloud blog](https://cloud.google.com/blog/topics/developers-practitioners/master-multi-tasking-with-the-jules-extension-for-gemini-cli/)
- **Warp Oz** (2026-02-10): a cloud orchestration platform that tracks every agent "with a link and an audit trail". It has a CLI, API, SDK, scheduler and web console, and since May 2026 can run Claude Code and Codex harnesses. — [Warp blog: Oz](https://www.warp.dev/blog/oz-orchestration-platform-cloud-agents); [Warp newsroom](https://www.warp.dev/newsroom/2026/2/10/warp-launches-oz-the-orchestration-platform-for-cloud-coding-agents)
- **Amp** (spun out of Sourcegraph Dec 2025): parallel subagents, "orbs" that run threads on remote machines, "Handoff" in place of compaction, and shared team threads. — [aiagentslist Amp](https://www.aiagentslist.io/agents/amp-code); [rywalker Amp](https://rywalker.com/research/amp-sourcegraph)
- **OpenHands**: the main repo is now branded "Agent Canvas", a self-hosted "always-on engineering team" that can run against multiple agent backends. It has an Agent SDK (MLSys 2026 paper) with blocking parallel sub-agent delegation. — [GitHub OpenHands](https://github.com/OpenHands/OpenHands); [MLSys 2026 paper](https://proceedings.mlsys.org/paper_files/paper/2026/file/8ae9cf363ea625161f885b798c1f1f78-Paper-Conference.pdf)
- **Factory**: Droids run from the CLI, desktop, web, Slack, Jira, Linear and CI. Factory acquired **HumanLayer**, a "multiplayer coding agent IDE" for running Claude Code and Codex locally or in the background, on 2026-11-04 and open-sourced it under Apache-2.0. This was Factory's third acquisition in under a month. — [Factory news: HumanLayer](https://factory.com/news/humanlayer); [The New Stack](https://thenewstack.io/factory-acquires-humanlayer-agents/)
- **Terragon Labs**: ran Claude Code and Codex in the cloud as background agents. The shutdown was announced 2026-01-11 and the service stopped 2026-02-09. An open-source snapshot remains (unmaintained). — [terragonlabs.com](https://www.terragonlabs.com/); [terragon-oss](https://github.com/terragon-labs/terragon-oss)

**"Agent town" / program-shaped orchestrators**
- **Gas Town** (Steve Yegge, released early Jan 2026; v1.0 about 3 months later): a Go/tmux orchestrator for 20–30 agents built on **Beads**, a git-backed issue tracker. Roles are Mayor (coordinator), Polecats (workers), Witness (per-rig health and stuck-agent detection), Deacon (cross-rig patrols), Dogs (maintenance), Refinery (merge queue), and the human "Overseer". Work is bundled into "convoys", and the `mountain` label enables stall detection for epic-scale work. The UI is `gt feed` (agent tree, convoy panel, event stream, and a "problems" view for stuck, stalled or zombie agents) plus a `gt dashboard` web view of agents, convoys, queues, issues and escalations. — [GitHub gastownhall/gastown](https://github.com/gastownhall/gastown); [Yegge: Clown Show to v1.0](https://steve-yegge.medium.com/gas-town-from-clown-show-to-v1-0-c239d9a407ec)
- Gas Town escalation: `gt escalate` takes severity CRITICAL, HIGH or MEDIUM and routes through Deacon, then Mayor, then the human Overseer. The Refinery is a Bors-style bisecting merge queue that merges to main only when verification gates pass, and Polecats never push to main. — [GitHub gastownhall/gastown](https://github.com/gastownhall/gastown)
- Yegge's Aug 2026 essay reports he stopped using Gas Town because agents kept tinkering with the orchestration instead of the app. He built a private orchestrator ("Wheelhouse") that still has Beads, planning agents, separate reviewers and merge processing. — [search summary of Yegge essay via ascii.co.uk / Medium](https://steve-yegge.medium.com/gas-town-from-clown-show-to-v1-0-c239d9a407ec) (secondhand; the essay itself was not fetched)
- **Multica**: an open-source "managed agents" platform with a Linear-shaped surface (issues, projects, comments, inbox, real-time updates) in which agents are assignees. Agents "report blockers and update statuses" themselves. A local daemon detects agent CLIs on PATH. It has a Go backend, Next.js web app and Electron app, and self-hosts via Docker or Helm. — [GitHub multica-ai](https://github.com/multica-ai); [research brief gist](https://gist.github.com/owainlewis/025500254690a23958d2e7f7b4846bcc)
- **Imbue mngr**: an open-source tool for orchestrating 100+ Claude agents. Each agent takes one issue, failed merges go to human review, and the integration step records which branches failed. `mngr connect` attaches to an agent's tmux session and `mngr message` broadcasts a tested prompt to many agents. — [HN discussion of Imbue case study](https://news.ycombinator.com/item?id=47629485)

**Thin monitoring dashboards**
- **ccdeck** (AGPL-3.0): a local dashboard for Claude Code and Codex CLI sessions, fed by hooks and Codex rollout logs. Sessions waiting on you sort to the top, longest wait first. It also shows tool calls, subagents and cost. — [GitHub ccdeck](https://github.com/BarganConstantin/ccdeck)
- Others: Lazyagent (TUI, desktop and HTTP API across 9 agents), 49agents (canvas), agent-view (tmux, with notifications on finish or needs-input), recon (working, idle and waiting table), and claude-tmux (unmaintained). — [runpane.com roundup](https://runpane.com/agent-dashboards)

### Inferences
- The center of gravity moved in 2026 from third-party worktree managers toward vendor-native multi-session views: Claude agent view (May), Projects (Sep), the Codex app (Feb), Cursor 3 (Apr) and Agent HQ (Oct 2025). Third-party tools are consolidating or dying.
- Gas Town, Multica and Claude Code Projects are the only catalogued tools that model anything above the individual task: convoys and epics, projects, or a long-lived coordinator. Everything else is session-centric.

### Gaps
- The Factory "Missions" feature could not be confirmed. No search result mentioned it.
- These tools were not investigated: Kiro and spec-driven tools (likely covered by other researchers), Linear's agent features, and JetBrains Air/Junie.
- Conductor's "Checks" docs page was listed but its content was not retrieved, so I could not confirm whether Conductor surfaces CI status per workspace.

## Q2. What does each show the human, and how much TRUTH / ATTENTION / COVERAGE does it provide?

### Takeaway
The working hypothesis is **confirmed**: almost every tool is a *session runner and diff reviewer*, not a program-awareness tool. ATTENTION exists only in a narrow form: "this session is blocked on a permission prompt or a question right now." No catalogued tool keeps a queue of *decisions agents made autonomously* for later ratification. TRUTH is partial at best. The strongest evidence signals are PR/CI state (Claude agent view and Projects, GitHub mission control) and merge-gate results (Gas Town's Refinery, Imbue mngr's failed-merge log). Task "done" status is still agent-reported everywhere, and Anthropic's docs admit it lags. COVERAGE (untouched in-scope work, deferred items, untracked findings) is essentially absent. Gas Town's stall detection and Anthropic's suggested "list what each thread assumed" prompt are the closest things to it.

### Cited Findings

**ATTENTION: "blocked now" queues exist, "decisions to ratify" queues do not**
- Claude agent view puts "Needs input" sessions above working ones. `waitingFor` names the blocker type (permission prompt, question, MCP input, sandbox, dialog), and notifications fire on needs-input, finish or fail via a `Notification` hook (`agent_needs_input`, `agent_completed`). — [Claude Code docs: agent view](https://code.claude.com/docs/en/agent-view)
- Claude Projects' Overview has a "Waiting on you" group for "threads that need your reply or approval, or that failed", a dot on the Overview button, and desktop notifications. A thread's approval prompt lives inside that thread, and "telling Claude in the project conversation to go ahead doesn't reach it." — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects)
- Anthropic's own troubleshooting for Projects describes the unratified-assumption problem directly: threads "assumed something wrong, worked around missing access, or stopped with 'blocked'". The recommended fix is a manual prompt asking Claude to list, for every thread, "what it assumed or couldn't reach, and what it's waiting on." — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects)
- Projects' memory stores "requirements, decisions, and pitfalls" as files Claude writes itself, and preferences given in conversation are "instructions Claude keeps to, not enforced settings." — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects)
- In agent teams, a teammate's plan approval request goes to the *lead*, and by default "Claude Code approves the plan as soon as the request arrives, without the lead reviewing it." The human is not asked. — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams)
- Gas Town has an explicit escalation channel to the human Overseer with P0, P1 and P2 severities, and its dashboard lists escalations. — [GitHub gastownhall/gastown](https://github.com/gastownhall/gastown)
- Devin can require human approval before child-session batches launch ("Auto-approve child sessions" off). — [Devin docs](https://docs.devin.ai/work-with-devin/advanced-capabilities)
- ccdeck sorts waiting sessions by longest wait. — [GitHub ccdeck](https://github.com/BarganConstantin/ccdeck)
- GitHub mission control's guide mentions no notifications, no plan or milestone view, and no queue of decisions or questions. Oversight relies on reading logs "as reasoning" and steering early. — [GitHub blog](https://github.blog/ai-and-ml/github-copilot/how-to-orchestrate-agents-using-mission-control/)

**TRUTH: evidence vs. self-report**
- Claude agent view's row summaries are produced by a Haiku-class model from the session's own output, so they are self-report. PR status, by contrast, is evidence: PR labels are colored yellow (waiting on checks or review, or checks failed), green (checks passed), purple (merged) and grey (draft or closed), and the docs say to merge "when the number turns green". The PR link itself is discovered from `gh`/`git` command output rather than by polling. — [Claude Code docs: agent view](https://code.claude.com/docs/en/agent-view)
- The Projects Overview "Ready for review" and "Landing" groups come from PR state (open, approved or queued to merge). "Resolved" can be set by Claude "once you've taken the last step, such as merging its pull request", or automatically after a week of inactivity. Threads watch their PRs with auto-fix, pushing CI fixes and replying "when checks pass." — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects)
- Anthropic recommends that project instructions require threads to "run `make test` and `make lint` and paste the summary lines in your final message", which is still evidence relayed by the agent rather than independently verified. — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects)
- Agent teams' known limitation: "Task status can lag: teammates sometimes fail to mark tasks as completed... check whether the work is actually done". The `TaskCompleted` hook can block a completion claim (exit 2), which is a hook point for evidence checks. The lead "can stop early too, deciding the team is finished before all tasks are actually complete." — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams)
- Gas Town's evidence is mixed. `gt done` pushes a branch and creates a merge-request bead, and the Refinery merges only after verification gates pass (evidence). Convoy completion, however, rests on agents "reporting completion" (self-report). — [GitHub gastownhall/gastown](https://github.com/gastownhall/gastown)
- In Multica, agents "report blockers and update statuses on their own" (self-report). — [research brief](https://gist.github.com/owainlewis/025500254690a23958d2e7f7b4846bcc)
- GitHub mission control tells reviewers to check "session logs, files changed, and checks" and to investigate failing checks rather than restart the agent. — [GitHub blog](https://github.blog/ai-and-ml/github-copilot/how-to-orchestrate-agents-using-mission-control/)
- Warp Oz gives every agent run a link and an audit trail. — [Warp blog](https://www.warp.dev/blog/oz-orchestration-platform-cloud-agents)

**COVERAGE / plan level**
- No plan, epic or milestone concept is documented for Vibe Kanban (issues on a kanban board only), Conductor, claude-squad, Crystal or Sculptor. — [Vibe Kanban GitHub](https://github.com/BloopAI/vibe-kanban); [Conductor docs](https://www.conductor.build/docs/); [claude-squad GitHub](https://github.com/smtg-ai/claude-squad)
- Gas Town groups work into convoys and molecules (multi-step workflow templates). The `mountain` label enables stall detection for epic-scale work, and the Witness and Deacon detect stuck agents. This is the closest thing to "in-scope work nobody is moving." — [GitHub gastownhall/gastown](https://github.com/gastownhall/gastown)
- Claude Projects has a coordinator that "sees what threads report back, not every step they take", so its view of the program is built from self-reports. — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects)
- Agent teams' task list has dependency-based "blocked" status and auto-unblocking, but it is scoped to a single session ("one team per session... can't share a team across sessions"), and the team config is deleted at session end. — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams)

**Worktree handling (summary)**
- Worktrees are the default in Conductor, claude-squad, Crystal/Nimbalyst, Vibe Kanban, Superset/Paradev, Emdash, the Codex app, Cursor 3, and Claude agent view (`.claude/worktrees/`, with deletion guarded by unpushed-commit checks). Sculptor uses Docker containers instead. Cloud agents (Projects threads, Devin, Jules, Oz, Copilot) use remote branches and VMs. — sources above; [Claude Code docs: agent view](https://code.claude.com/docs/en/agent-view); [Imbue Sculptor](https://imbue.com/sculptor/)

### Inferences

Pillar matrix (my assessment from the cited docs; ● strong, ◐ partial, ○ none):

| Tool | TRUTH (evidence-based status) | ATTENTION (blocked now) | ATTENTION (decisions to ratify) | COVERAGE / plan level |
|---|---|---|---|---|
| Claude agent view | ◐ PR/CI colors; summaries self-reported | ● needs-input + waitingFor + JSON | ○ | ○ |
| Claude Projects | ◐ PR/CI-driven groups | ● Waiting on you | ○ (memory holds decisions, unreviewed) | ◐ coordinator, self-report-based |
| Claude agent teams | ○/◐ self-marked tasks; TaskCompleted hook | ◐ (permission prompts bubble to lead) | ○ (plans auto-approved) | ◐ in-session task DAG only |
| Gas Town + Beads | ◐ merge-gate evidence; convoy completion self-reported | ● escalations w/ severity | ○ | ◐ convoys, stall detection |
| Multica | ○ agent-updated statuses | ◐ inbox/blockers | ○ | ◐ issues/projects |
| GitHub mission control | ◐ checks + PR | ◐ steering, no queue | ○ | ○ |
| Devin / Managed Devins | ◐ PRs | ◐ batch approval | ○ | ○ |
| Conductor / Nimbalyst / claude-squad / Vibe Kanban / Emdash / Paradev / Sculptor | ○–◐ diffs, PRs | ◐ per-session indicators | ○ | ○ (kanban of tasks at most) |
| Codex app / Cursor 3 | ◐ diffs, PRs | ◐ | ○ | ○ |
| ccdeck / Lazyagent / recon | ○ | ● waiting-first sorting | ○ | ○ |

- The "decisions an agent made autonomously, pending ratification" queue is a clear white space. Anthropic's own docs prescribe a manual "list what each thread assumed" prompt, which is direct evidence the need is real and unmet.
- "Done" in every tool means "the agent says done" or "the PR is green/merged". No tool cross-checks tracked status against the repo (branch merged? tests for the claimed feature exist and pass?) or flags drift between the plan and git.
- Hook points exist for building TRUTH on top of Claude Code: `TaskCompleted` exit-2 vetoes, the `Notification` hook types, and `claude agents --json` with `state`/`waitingFor`/PR info. A new tool could consume these rather than re-implement session running.

**Verdicts**
- **Claude Code agent view (`claude agents --json`)**: *use directly* as a data source. It is the user's main agent, gives machine-readable needs-input/PR state for free, and is the cheapest ATTENTION feed.
- **Claude Code Projects**: *learn from*. Its Overview state taxonomy (Ready for review / Waiting on you / Landing / Resolved) and its "threads guessed instead of asking" troubleshooting confirm the problem. But it is a cloud beta that requires a GitHub App, its coordinator reads only self-reports, and it does not cover local parallel worktrees.
- **Claude Code agent teams**: *copy ideas*. The TaskCompleted veto hook is the right primitive for evidence-gated completion. The product itself is session-scoped and ephemeral, so it cannot hold a multi-day program.
- **Gas Town + Beads**: *copy ideas*. Its escalation severities, stall/zombie "problems" view, merge-queue-as-evidence, and git-backed work ledger are the closest prior art to TRUTH and ATTENTION. Its author abandoned it because the orchestration became the work, and it is too heavy to adopt directly.
- **Beads alone**: *learn from / possibly use*. A git-backed issue ledger is close to mull's own model. It is worth comparing for schema ideas (24K+ stars per secondary source).
- **Multica**: *learn from*. It shows a Linear-shaped "agents as assignees" surface with an inbox, but statuses are self-reported and it is server-heavy for a solo Mac user.
- **Imbue mngr**: *copy ideas*. Recording failed merges at integration and broadcasting one fix to many agents are both useful. It targets fleets of 100 test agents, not program oversight.
- **Conductor**: *use directly* as a session runner if a GUI worktree manager is wanted. It is the best-regarded Mac cockpit, but it offers no program view, so it complements rather than replaces the new tool.
- **Nimbalyst**: *learn from*. Its session kanban and visual markdown/diagram editors fit a "GUI cockpit", but it has no evidence or decision layer.
- **claude-squad**: *learn from*. It is a minimal tmux+worktree TUI and a good model of a low-friction session list. It is AGPL-3.0 and offers no oversight features.
- **Vibe Kanban**: *learn from*. Kanban plus per-card worktree plus inline diff feedback is a nice UX, but the company is gone (sunsetting since Apr 2026) and it does not track decisions.
- **Crystal**: *skip*. It is deprecated (Feb 2026) and superseded by Nimbalyst.
- **Sculptor**: *learn from*. Container isolation and "instruction audits" are interesting, but it is Claude-only and session-centric.
- **Superset/Paradev, Emdash**: *learn from*. Both are healthy worktree managers that bring nothing new for TRUTH, ATTENTION or COVERAGE. Emdash is pivoting to team cloud.
- **ccdeck / Lazyagent / recon**: *copy ideas*. "Longest-waiting first" sorting via hooks is exactly the ATTENTION-queue ordering rule.
- **GitHub Agent HQ / mission control**: *learn from*. The "session logs + files changed + checks" review triad is a useful model. It is tied to GitHub cloud and Copilot plans and has no decision queue.
- **OpenAI Codex app / Cursor 3 Agents Window**: *learn from*. Both are polished parallel-thread UIs, but they are not the user's primary agent and have no program layer.
- **Devin (Managed Devins)**: *learn from*. The coordinator/child structure with an optional human gate before batch launch is interesting. It is a commercial cloud product and not Claude Code.
- **Warp Oz**: *learn from*. Its per-run link and audit trail is a good TRUTH-adjacent idea. It is a cloud and credits product.
- **Amp**: *learn from*. "Handoff" between threads in place of lossy compaction is relevant to keeping agents on the same page.
- **OpenHands / Agent Canvas**: *learn from*. It is a self-hostable agent backend, overkill as a cockpit.
- **Factory / HumanLayer**: *learn from*. HumanLayer was just open-sourced (Apache-2.0) and may be worth mining, but its future is uncertain after the 2026-11-04 acquisition.
- **Jules, Terragon**: *skip*. Both are dead or dying (Jules winds down 2026-12-31; Terragon shut down 2026-02-09).

### Gaps
- Conductor's notification behavior, Checks page and Linear integration details were not verified from primary docs.
- Nimbalyst's "built-in task tracking" was not inspected in detail, so its depth (plans? milestones?) is unknown.
- No source showed any tool detecting drift between a written plan and git history, and no tool claiming a decision-ratification queue was found. I report that absence as a finding, but a more exhaustive search of smaller GitHub projects might turn one up.

## Q4. Practitioner reports: what goes wrong with oversight when running many agents, and how people keep track

### Takeaway
Practitioners consistently report that human review is the bottleneck. Agents drift into inconsistent versions of "reality". Decisions stay trapped inside individual chats. Agents stop early or report done prematurely. Failures are invisible without aggregation. Common coping strategies are: fewer, well-partitioned agents (2–5); detailed specs before dispatch; parallelizing only low-attention work; a central activity log reviewed after the fact; and, at scale, treating transcripts as a dataset. The concerns line up closely with the target tool's TRUTH, ATTENTION and COVERAGE goals.

### Cited Findings
- Simon Willison (Oct 2025) runs several Claude Code and Codex sessions in parallel but says "I can only focus on reviewing and landing one significant change at a time." Specified work is "a lot less effort to review". He parallelizes research, small maintenance and pre-specified tasks, and uses fresh checkouts in /tmp rather than worktrees. — [simonwillison.net](https://simonwillison.net/2025/Oct/5/parallel-coding-agents/)
- HN discussion of Willison's post: "review is hands down the biggest bottleneck". One commenter said they "can trust nothing and have to verify every assumption". Others said seeing AI solutions biases the reviewer, and that keeping environments and branches straight becomes a complex coordination problem. — [HN 45489884](https://news.ycombinator.com/item?id=45489884)
- HN on tmux and Markdown specs: commenters prefer 2–3 focused agents over 6–8 competing ones, and say parallel agents "lose track of which version of 'reality' applies" to each component. — [HN 47218318](https://news.ycombinator.com/item?id=47218318)
- HN on Imbue's 100+ agents: "behavioral drift between parallel agent instances is nearly invisible without something aggregating" what they do. Another commenter said that at scale "you're debugging distributions, not individual runs" and recommended pattern detection and alerting. — [HN 47629485](https://news.ycombinator.com/item?id=47629485)
- HN "20+ Claude Code agents coordinating": multi-agent setups make it easier to drift away from human oversight. A suggested remedy was logging everything to a central activity stream, since you can't watch 20 agents live but can review what happened. — [HN 46990733](https://news.ycombinator.com/item?id=46990733)
- An analysis of 663 HN comments (Nov 2026) says monitoring and session coordination are the primary bottlenecks beyond about 5 concurrent agents, and counts 105 developers using git worktrees for isolation. — [techbytes](https://techbytes.app/posts/ai-coding-agent-setups-from-663-hacker-news-comments/)
- HackerNoon (~Oct 2026): parallel agents fail *between* agents, through "decisions that stay in one chat", code that no longer fits, and handoffs that lose context. — [HackerNoon](https://hackernoon.com/four-ai-coding-agents-one-codebase-and-a-coordination-problem)
- Anthropic's docs list these failure modes for teams: task status lags, the lead declares the team finished before tasks are complete, teammates stop early after errors, and "letting a team run unattended for too long increases the risk of wasted effort." They recommend 3–5 teammates. — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams)
- GitHub's warning signs for mission control: failing tests, unexpected files in the diff, scope creep, misread intent, and circular retries. Its advice is to steer early and batch similar reviews. — [GitHub blog](https://github.blog/ai-and-ml/github-copilot/how-to-orchestrate-agents-using-mission-control/)
- Devin reviewers report a common failure mode: two sessions edit the same package and the branch "turns into a merge puzzle". They also cite autonomous completion of roughly 14–30% on complex or ambiguous work (third-party estimate). — [amrytt review](https://amrytt.com/devin-ai-review/); [syntaxdispatch review](https://www.syntaxdispatch.com/blog/devin-review)
- Yegge reports abandoning Gas Town because agents kept working on the orchestrator instead of the application. — [search summary of Aug 2026 Yegge essay](https://steve-yegge.medium.com/gas-town-from-clown-show-to-v1-0-c239d9a407ec) (secondhand)
- Imbue's approach relies on small, well-isolated components, tests linked to a human-readable behavior document, and logging failed merges. — [HN 47629485](https://news.ycombinator.com/item?id=47629485)

### Inferences
- The oversight failures practitioners describe are *program-level*: drift across agents, buried decisions, premature "done", and unnoticed gaps. The tools catalogued above solve *session-level* problems (isolation, diff review, needs-input pings). This mismatch is the opportunity for the target tool.
- The "central activity stream reviewed later" and "transcripts as a dataset" suggestions support an independent auditor agent that reads transcripts and git after the fact rather than trusting live self-reports.
- The meta-risk Yegge describes (orchestration becoming the work) argues for keeping the new tool read-mostly and lightweight, deriving state from git and Claude Code's existing JSON/hooks instead of building another session runner.

### Gaps
- Few first-hand, long-form accounts were found of a *solo* developer running a multi-day, multi-milestone program across dozens of sessions. Most reports cover parallel task bursts or team or enterprise fleets.
- The Hacker News thread dates are relative ("7 months ago"), so exact dates were not confirmed for some threads.
