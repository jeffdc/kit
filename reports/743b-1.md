## How it was built

### Design notes

All of the tour logic is in one new file, internal/mull/tour.go, and both readers use it. tourParts splits a step into text and paths, and resolves each path against the preview. resolveTourStep joins the parts back into text with full URLs, for report's markdown. resolveTour gives the parts per step, for mull serve's review packet (Review.tour). tourWarnings is done's soft check. Because the server splits the steps, the JS only renders the parts, and the path rule exists only in Go.

Resolution happens when a report is read, never when it's written. The report keeps the steps as the agent wrote them, and ReportText and the item page look up the item's plan's preview each time. That way a preview set or changed after done still applies, and with no preview the steps read as written. For the markdown, resolveReportText rewrites only the "N. step" lines in the "### UI tour" section of the stored body and leaves the rest alone, so reports rendered by older mull keep their text. I rejected re-rendering the whole report from its structured fields because that would quietly reformat old reports. ReportText now returns a ReportOut struct ({report, text, preview}), which the report command prints as-is. That adds a `preview` key to report's JSON.

Path rule: a "/" at the start of a step or after a space, an opening bracket or a quote, running to the next space, closing bracket or quote, with trailing sentence punctuation (.,;:!?) trimmed off. "//" is skipped, and so is a path inside a URL, because its "/" follows the host. Joining: preview scheme + host + path, without its trailing slash, query or fragment, then the step's path. I rejected net/url ResolveReference because it would drop a preview's base path (https://example.com/app). mull's own demo works too: preview http://localhost:6899 plus /#/demo/... gives the right URL.

Warnings: a full http(s) URL, or a scheme-less localhost:port / 127.0.0.1:port, whose host is local (localhost, *.localhost, 127.0.0.1, 0.0.0.0, ::1, with IPv6 brackets kept) and whose scheme and host:port differ from the preview's. With no preview, every local URL warns. Each warning names the path to give instead. Hosts that aren't local are left alone. The warnings go into DoneResult.warnings and model.Report.warnings (stored with the report and rendered under the tour as "**Warning:** …"). They never stop done, including when the checks fail.

mull serve: item.js has a small tour() function that renders review.tour (falling back to the plain steps). Path parts are links in a new tab with the construction-line underline that prose links use. A muted line names the preview (also a link) and the target, with a note when the work isn't on the target yet (git.seen_in_git). Warnings are ink rv-notes, never red (the One Mark, One Job rule). DESIGN.md's Review packet section describes it.

Guides: the agents guide (and kit's AGENTS.md copy, kept identical) says to name pages by path, explains why, says done warns about other local URLs, and says the work reaches the preview only after the supervisor merges it. The supervisor guide's review section now states the order (done, review the diff, merge into the target, Jeff walks the tour on the preview, accept) and adds checking warnings. design.md's preview section and json.md (Report.warnings, done.warnings, report.preview, the item page's review.tour/preview) are updated. The make dev demo (scripts/dev-demo.sh) gives the web plan a preview and the digest job a tour with one path step and one stray-local-URL step, so the packet shows both a resolved link and a warning.

Bench (make bench, large seed, in-process ms, before → after): item in-review 30.3 → 29.7, item active 29.7 → 29.2, item done 29.4 → 28.3, overview 47.5 → 44.3, load 283.4 → 275.1. Git calls are unchanged (2 per item page). The item page bytes for the in-review item went 7041 → 7214 from the tour parts. No measurable cost: the added work is a regex over a few tour lines per page.
