# Done report 1: Agents call the human by name in what they write to mull, not 'the human' (64e7)

## What was built

### Summary

A repository can name its human: mull config set human <name> ("" clears it). mull's own words then use the name: every guide (so mull guide agents, which AGENTS.md copies), mull context's protocol, done's reminder, start's warnings and error messages, batch lines included. The agents guide and the protocol open with a rule telling agents to write the name, not 'the human', in what they write to mull. Stored records aren't rewritten; unnamed, nothing changes. kit is set to Jeff and its AGENTS.md block is regenerated from the guide (and its plan list updated). Takes effect for agents once the new mull is installed (make install).

## How it was built

### Design notes

model.Config gains human (yaml omitempty, so existing configs are unchanged); configSet accepts it and treats empty as clearing. internal/guide gets Personal(text, name), a regexp swap of 'the human' and 'the human's' (either case) for the name that skips hyphened compounds ('the human-feedback rule') and leaves 'a human' and 'humans' alone, plus NameRule(name), the explicit instruction, and For(guide, name), which personalizes a guide and puts the rule after the agents guide's opening paragraph.

Where it applies: mull guide (cmd opens the repo best-effort; outside one the guide is as written), Context's protocol (rule first, every line personalized, including the migration line), done's reminder and start's shaping warning (m.personal), and every error the CLI prints, personalized in Execute on a copy of the error, batch line errors included, since errf has no repository to ask. Stored records are never touched: rewriting what agents wrote would misstate the record. Cobra help strings stay static.

I chose config on the mull branch over per-machine state: every agent in the repo reads the same branch, it syncs, and config is already the human's. The name is per repository, so gallformers and the repos still to come each set theirs.

Tests: guide.TestPersonal (cases, hyphen, no name), cmd.TestHumanName (unnamed guide unchanged; named: config shows it, the agents guide has the rule and Jeff, the triage guide has no 'the human', context's protocol starts with the rule and no line says 'the human', a not_allowed error says 'only Jeff creates a plan'; clearing restores the guide byte for byte). kit's AGENTS.md block was an exact copy of the guide before, so it's regenerated with mull guide agents --text from this build.

### Decisions made in the session

Accepting the review ratifies these. To decide one differently, before accepting: `mull decide <id> "..."`

- **0d6d** Only mull's own words are personalized (guides, the context protocol, done's reminder, start's warnings, error messages); stored records are never rewritten, and cobra help text is left as written
  Why: Rewriting what agents already wrote would misstate the record; help text is static and rarely what agents copy from.
- **74d3** The human's name is a per-repository config key on the mull branch (mull config set human <name>; empty clears it), not per-machine state
  Why: It's what every agent working in the repo reads, it syncs with the repo, and config is already the human's to set.
- **8e7b** Substitution is 'the human' / 'the human's' (either case) to the name, skipping hyphened names like 'the human-feedback rule'; and an explicit rule (write <name>, not 'the human') opens the agents guide's body and the protocol
  Why: Agents copy the protocol's wording, so changing the wording is most of the fix; the rule covers what they write unprompted.
- **b065** kit names Jeff, and kit's AGENTS.md 'Working with mull' block is regenerated from the personalized mull guide agents
  Why: Jeff asked for agents to use his name; AGENTS.md is a copy of the guide, so it's regenerated rather than edited.
