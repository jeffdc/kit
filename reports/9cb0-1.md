## What was built

### Summary

mull serve exists: every mull command registers its repo in ~/.config/mull/repos (main worktree, only repos with a mull branch, best effort), and mull serve listens on 127.0.0.1:6855 (--port to change), serves an embedded placeholder page and GET /api/projects, a lean summary per registered repo (plans, needs-you counts, agents, untriaged, refs, last change) or the mull error for one it can't read. It is the base the JSON API (5b48), SSE (35f5) and last-looked (3deb) items build on.

## How it was built

### Design notes

Shape: three new packages, each with one job. internal/registry is the per-machine repo list (plain text file, Dir/File/Register/Add/Repos); internal/serve is the HTTP handler over an injected Repos func, with the UI embedded from internal/serve/web; cmd/serve.go only binds the port, prints the start JSON and handles shutdown. The project row is Mull.Summary in internal/mull, so reads still go through internal/mull as the item asked.

Registry: registered after each command in cmd.Execute (so mull init counts), keyed by the main worktree (git rev-parse --git-common-dir) so every linked worktree of a repo is one project, and only when refs/heads/mull exists so mull guide in an unrelated repo adds nothing. Errors are ignored: a read-only home must never break an agent's command. Concurrent appends can duplicate a line; Repos reads each path once, which is simpler than locking. $XDG_CONFIG_HOME is honoured, and gittest.Isolate plus a cmd TestMain point it at a temp dir so tests never touch the real registry.

Summary vs Board: Board calls readGit, which walks every local branch for item links; the project list doesn't need those and may cover many repos, so Summary reads the records, the mull tip's commit time and two refs for ahead-of-release. To avoid copying, I extracted NeedsYou.add (Board's per-entry counting) and Mull.aheadOfRelease (readGit's rev-list) and both callers use them; Board's behaviour is unchanged and its tests pass. Blocking counts and revisions are deliberately left out: they belong to 5b48's ranking and 3deb's last-looked state.

Server: Go 1.22 method patterns (GET /api/projects, GET /api/ for JSON 404s, GET / for embedded files; POST gets 405 for free). Repos is re-read per request so repos registered while serve runs appear without a restart, and summaries are read concurrently. Unreadable repos are listed with their mull error code rather than dropped (nothing gets lost). A localOnly wrapper refuses any Host other than localhost/127.0.0.1, which closes DNS rebinding against a localhost API at almost no cost. Project IDs are directory names, with -2/-3 for clashes in registration order so IDs stay stable.

Rejected: os.UserConfigDir (it's ~/Library/Application Support on macOS, the design says ~/.config/mull); a --host/--addr flag (local-only is the point); a JSON registry file (a path per line is editable by hand); calling Board per project (slow and more than the list needs).

The placeholder page is plain index.html + app.js module + style.css, no build step, in light and dark, so the UI phase has the pattern to replace. Verified by running the binary against kit in a scratch config: counts match mull inbox and mull list --untriaged, a missing path shows not_a_repo, foreign Host gets 403, second serve gets port_in_use; screenshots in both themes.

### Decisions made in the session

Accepting the review ratifies these. To decide one differently, before accepting: `mull decide <id> "..."`

- **06db** New error code port_in_use when mull serve's port is taken
  Why: Lets a script or agent tell 'already running' from other failures
- **6da7** A project's URL ID is its main worktree's directory name; on a clash the first registered keeps it and later ones get -2, -3
  Why: Readable URLs (/kit) that stay put as more repos are registered
- **7639** The registry is ~/.config/mull/repos (or $XDG_CONFIG_HOME/mull/repos, on macOS too): one main-worktree path per line, # comments and blanks skipped, duplicates read once
  Why: Plain text the human can edit; main worktree so every linked worktree of a repo is one project; XDG lets tests isolate it
- **923d** mull serve answers only requests whose Host is localhost or 127.0.0.1 (403 not_allowed otherwise)
  Why: Stops a web page reading the API through DNS rebinding to 127.0.0.1
- **b657** GET /api/projects is {projects: [{id, name, path, summary?|error?}]}: a repo that can't be read is listed with its mull error code, not hidden; Summary is a lean per-project row (Mull.Summary) that reads records and a few refs, not the view's per-branch item links
  Why: Nothing gets lost silently; the list stays fast across many repos. Blocking and revision are left to 5b48 and 3deb
- **be3b** The UI is embedded from internal/serve/web as plain files (index.html, app.js module, style.css) served with Cache-Control no-cache; the registry is re-read on every API request
  Why: No build step, a new binary's files are picked up at once, and repos registered while serve runs appear without a restart
- **c38b** Every command registers its repo after it runs (so init counts), only if the repo has a mull branch, best effort: registration never fails or slows a command beyond two git calls
  Why: A non-mull repo or an unwritable config dir must not break agents' commands
- **d3f6** mull serve's fixed port is 6855 ('MULL' on a phone keypad), --port to change; it binds 127.0.0.1 only, with no flag to bind elsewhere
  Why: Local-only by design; a host flag would invite exposing the record
