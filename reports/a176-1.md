## How it was built

### Design notes

The human chose (asked in the session) that archived means closed: a plan in state done. So there's no model change, only the three places the UI was missing.

Close. plan close joins uiOps, the ops mull serve's ops endpoint accepts from pages, and the plan sheet's action row gains writeButton({op: "plan close"}) for active plans. mull plan close doesn't require finished work, so the button doesn't either; its armed question says when phases aren't done. Shaping plans don't get it (agreeing them is d1c5's job). The refused-op test used plan close as its example of an op the UI doesn't offer; it now uses add.

Archive in the tree. TreePage returns archive: the done plans, newest closed first (Updated is when it was closed, as nothing writes a closed plan). tree.js adds an Archive node after Backlog when there are any: no link of its own, faint, collapsed by default like Built, its rows reusing the pl: key so an archived plan's row is the current row on its sheet. expandFor opens Archive for an archived plan, and the write path now calls expandFor after reloading, so closing the plan on screen doesn't make its row vanish.

Search. Each search doc carries Archived (the record is a closed plan or belongs to one, by its plan field; an entry with no plan takes its item's). Search(q, limit, archive) leaves archived matches out unless archive, counting them in Found.Archived; /api/search takes archive=1 and sums the counts across projects. The palette resets to open-only each time it opens, and its foot offers 'Search the archive too: N more' as a small plain button, which reruns the search with the archive.

Aged-out done work (c32c) isn't archived: unplanned work has no plan to close, and the human asked to archive plans. It stays searchable by default.

Checked in headless Chromium against make dev with the large seed and the demo: the Archive row (22 plans), a closed plan's sheet, Find leaving out and then including the archive, and closing a plan from its sheet (toast, State field, tree row current under the opened Archive).
