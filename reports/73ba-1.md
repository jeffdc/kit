## What was built

### Summary

mull config checks and mull plan checks, on the CLI and as batch ops, are now refused (not_allowed) unless an agent passes --on-request, so an agent can't change the checks that judge its own work. The human acting through mull serve (AsHuman) needs no flag, as with every other human-only step. This reverses d359, per Jeff's decision ac81. design.md (a new 'Only the human changes the checks' note under Trust, plus the command table), mull guide json (not_allowed list, plan checks row, batch fields), the agents and supervisor guides, kit's AGENTS.md copy, context's protocol line, intake, README and the dev demo script are updated.

None given.

## How it was built

### Design notes

The gate reuses the existing human-only pattern: Mull.asked(onRequest), which is true for an agent that passes --on-request or for a Mull made by AsHuman (mull serve's writes). configChecks and planChecks take an onRequest argument and refuse with CodeNotAllowed before writing anything; ConfigChecksIn and PlanChecksIn gain an `on-request` batch field, and the batch op field lists in ops.go say so. The exported ConfigChecks and PlanChecks take onRequest as a parameter, as Migrate does, rather than a separate unguarded entry point, so no Go caller can bypass the gate by accident.

The cobra commands now bind a package-level In struct with an --on-request flag, matching plan agree.

The refusal comes before the unchanged-list shortcut and applies to clearing too: any write to the checks is a change to what judges agents' work. For plan checks the plan lookup comes first, so an unknown slug still says not_found, as plan agree does.

mull serve's pages don't offer config checks or plan checks (its op allowlist is unchanged), so nothing changes in the UI; the design note says the human's serve writes would need no flag.

Tests: TestChecksAreTheHumans covers refusal for both commands directly and as batch lines (no commit written), clearing, and the human (AsHuman) passing without the flag; cmd tests check the not_allowed exit on both CLI commands. Existing tests and the dev demo script pass on-request where they set checks. No read path changed, so no bench run.
