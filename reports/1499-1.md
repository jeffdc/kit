## How it was built

### Design notes

How it's built: one new file, internal/mull/worktrees.go, read-only throughout. It reads `git worktree list --porcelain` (one call), skips the main worktree, and matches each linked worktree by path to the items claimed from it, with the latest claim standing for it. For each row it reuses what readGit already derived: the item's plan target and seen_in_git, and the target's cached history, to tell whether the worktree's HEAD and the claim branch are on the target (a lookup in the history mull already read, falling back to `git merge-base --is-ancestor` only past the 5000-commit read). Clean is `git status --porcelain` in that worktree, which counts untracked files and leaves out ignored ones, the same rule `git worktree remove` applies, so "prunable" means git's own removal would go through without --force. The size is a Go walk summing regular files (not `du`, since all subprocesses should be git and this is portable).

Prunable = item done, seen in git on its target, HEAD and claim branch on the target, clean, not locked, and no target or release branch checked out there; `why` names the first test that fails. The commands are `git worktree remove <path>` and then `git branch -d` for the branch checked out there and the claim branch when it's another one (only branches that exist, aren't targets, release or mull, and aren't checked out in a different worktree), shell-quoted. mull never runs them.

Where it shows: `mull worktrees` (JSON, measures every row afresh); `mull view` gets a top-level `prunable_worktrees: {count, bytes}` and a WORKTREES line; mull serve's overview gets the same field and an ink `.note` above the revision schedule. I made it project-level rather than a per-plan problem kind because plans get closed before their worktrees are cleaned up, and a closed plan has no board in the view, which would hide exactly the oaks-style leftovers. With `--plan` it counts that plan's only. That departs from the phase doc's word "problem", and it's recorded as decision d69b for review.

Cost: serve reads the overview after every write, and walking gigabytes of deps each time is out. So the view and overview measure only rows that pass every other test, and cache (path, HEAD) measurements for five minutes; and before any git call they check whether any done item was claimed from a linked worktree still on disk (its `.git` is a file), skipping `git worktree list` entirely when none was. readGit now keeps the branch heads it already reads (gitState.Heads), so the worktree code doesn't call for-each-ref again.

Rejected: a `--text` rendering (the CLI is for agents, and the supervisor shows Jeff the commands); a per-plan problem (above); computing sizes with `du`; listing unclaimed worktrees or the main one.
