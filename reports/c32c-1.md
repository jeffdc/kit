# Done report 1: Done work ages out: done and dropped items more than 14 days old leave the tree and the unplanned list, still reachable (c32c)

## What was built

### Summary

Done work ages out of the lists that grow with it. Done and dropped items that last changed more than 14 days ago, with nothing open on them, leave the sheet index and the Unplanned list (and the Unplanned count); they stay on their phase's and their own sheets. Unplanned ends with 'N done or dropped items more than 14 days old are left out. Show all', linking to #/<project>/unplanned/all. Storage is unchanged. Entries are now indexed by item on cached states, so per-row question counts, open reviews and open decisions stop scanning the whole inbox per item (76e5). Large seed over HTTP: tree 54ms/60KB -> 23ms/32KB, Unplanned 43ms/125KB -> 20ms/26KB. This addresses 1f0b.

### UI tour

1. In mull/: register the large seed with the dev server: (cd .dev/bench/large && XDG_CONFIG_HOME=../../cfg ../../../mull list >/dev/null), then make dev.
2. Open http://localhost:6899/#/large/unplanned: about 31 rows (open and recent work), the tab says Unplanned 31, and under the table: '270 done or dropped items more than 14 days old are left out. Show all'.
3. Click Show all: every unplanned item (about 301), and the line 'Showing done work of every age. Only the last 14 days'.
4. Open the metrics plan in the sheet index and expand a phase: done items older than 14 days aren't listed; open the phase's sheet and they are.
5. make dev-stop.

## How it was built

### Design notes

The measurement first: on the large seed only two pages carry done work that grows without bound. The tree listed 203 done or dropped items across live phases, and Unplanned 274 (every unplanned item ever finished). Plan pages carry no item rows, and a phase sheet is bounded by its phase, which is the record of that phase, so they keep everything.

agedOut(item, now) is the one rule: done or dropped, last updated more than doneShownFor (14 days) before now, and no unsettled or parked entry on it. The open-entry exception matters because the tree counts each open entry on the row that lists its item; hiding the item would move the count up to its plan. The rule takes now as an argument rather than being cached with the state, since a cached state outlives the day.

TreePage filters through it (and now lists a phase's items from the items-by-phase index instead of scanning every item per phase). UnplannedPage(all) filters unless all is set and reports aged_out and done_shown_days; the API passes ?done=all. counts() takes now so the Unplanned count matches the list: a tab reading 301 over 31 rows looked broken in the screenshot.

UI: href.unplanned(pid, all) gives #/<pid>/unplanned/all; subsFor maps it to the API sub 'unplanned?done=all', app.js accepts 'all' as the only id under unplanned, and unplannedBody adds one muted .empty line with a plain link, which is navigation, so it's neither a copy nor a write action under DESIGN.md's two-kinds rule. No new styles.

Storage stays as it is. With the read cache, done work no longer costs every request, and archiving on the branch would need a migration and teach every reader a second place to look. Phase 1's numbers were the test for that, and they say not needed.

Also here: entries indexed by item on read-only states (itemEntries), used by itemRow's question count, openReview and openDecisions, which each scanned every inbox entry per item (76e5). Writes keep the scan.

Checked in a headless Chromium against make dev serving the large seed: the Unplanned list, its footer line, the tab count, the all view, and a plan's sheet index.

### Decisions made in the session

Accepting the review ratifies these. To decide one differently, before accepting: `mull decide <id> "..."`

- **0600** An aged-out item stays listed while anything on it is open (an unsettled or parked entry)
  Why: The tree counts an open entry on the row that lists its item; hiding the item would move the count to its plan and lose the thread.
- **315c** Done and dropped items age out of the sheet index and the Unplanned list 14 days after they last changed (one constant, doneShownFor)
  Why: Long enough to see what just finished across a two-week stretch; the window is the human's to change.
- **40e3** Aging out is only in the views (the tree and Unplanned); storage is unchanged, phase sheets list every item, and Unplanned shows everything at /unplanned/all (API ?done=all)
  Why: With the read cache, done work no longer costs every request (pages are 20-45ms on 5000 items), so moving records in storage, which needs a migration, isn't worth it.
- **79a2** The Unplanned count (tab and sheet index) counts what the list shows, so it leaves out aged-out work too
  Why: A tab reading 301 over a list of 31 looked broken.
- **9c2a** Entries are indexed by item on read-only states (itemEntries), used by itemRow's question count, openReview and openDecisions
  Why: Each of those scanned every inbox entry per item (bug 76e5); writes keep the scan, as with items by phase.
