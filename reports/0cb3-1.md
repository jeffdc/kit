## What was built

### Summary

make install no longer makes macOS announce mull as a new background item on every rebuild. It signs the binary with the keychain's Apple Development identity and the fixed identifier mull, so each build is the same item, and restarts the LaunchAgent with launchctl kickstart instead of rewriting its plist. ## How it was built

### Design notes

The notification came from macOS's background-items check: Go's linker gives every build an ad-hoc signature with identifier a.out and no team ID, so each install looked like a new program behind the mull.serve LaunchAgent. The fix is in the Makefile only. SIGN_ID defaults to the first "Apple Development" identity from security find-identity (by its SHA-1, so no name or email lands in the repo); SIGN_ID= or no identity skips signing, and a failed codesign only prints a note, so make install still works on any machine. codesign -f -i mull gives a stable identifier plus the team ID. The restart now uses launchctl kickstart -k, which leaves the plist alone (rewriting it also changed the embedded PATH from whatever shell ran make), falling back to mull serve --install when the agent isn't loaded. I rejected launching through /bin/sh as the first try because Login Items would then show sh instead of mull. design.md's LaunchAgent paragraph now says this.
