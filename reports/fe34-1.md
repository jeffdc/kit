## How it was built

### Design notes

CaptureItemIn (internal/mull/ops.go) gains a Title field (json "title") next to the existing Text (json "text"). run takes Title, or Text when Title is empty; both given is invalid_argument, whether or not they match, so there's one rule and no guessing which wins. The ops table's desc for bug and idea now reads "title, plan, phase, category, source, detail", which is what the batch "bad fields" error lists, so the alias stays silent there too. I kept text as a real struct field rather than a custom UnmarshalJSON because parseLine decodes with DisallowUnknownFields, and a plain field is the simplest way to let the alias through. The CLI's mull bug/idea sets Title from the positional argument. mull serve's capture.js sends title now, since it's the canonical name; the serve test posts title and checks the stored titles. Tests: TestCapturesInBatch uses title for the bug and text (the alias) for the idea and checks both titles; the new TestCaptureTitleInBatch covers both-given, no title, and an unknown field's error listing title and not text; TestTriageInBatch uses title. Older tests that send text (similar_test, batch_test) still pass, which covers the alias. docs/design.md doesn't spell out bug/idea batch fields, so it needed no change.
