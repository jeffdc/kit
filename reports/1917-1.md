## What was built

### Summary

Items gain a rank: their order among a group's open work (a phase, a plan's items with no phase, or Unplanned). mull rank <phase|plan|none> <ids...> sets a group's order, strictly listing every committed, active and in-review item (ed34), and mull writes ranks 10 apart. Committed work joins its group last on add, commit, start of a captured item and a move to another phase, and add --before/--after places it next to an open item. Rank is in the batch ops, the change feed and mull guide json. The lists aren't sorted by rank yet and start doesn't warn: that's b2b6.

## How it was built

### Design notes

The model gains one field, Item.Rank (yaml rank, omitempty), where 0 means unranked. There's no format bump and no migration: old items just have no rank. All the logic is in a new internal/mull/rank.go:
- group/groupOf say where an item is ordered (phase, else plan, else Unplanned), and openWork says which stages a rank orders.
- rankLess is the one comparison (ranked before unranked, then by rank, then oldest first), so b2b6 can sort every list with it.
- ranked lists a group's open work in that order.
- place is the single placement helper. addItem, commit, start of a captured item and set phase call it, so the do and accept follow-up paths, which go through addItem, rank their new items with no extra code. It takes the midpoint of the gap at the spot (or lo+10 at the end), and renumbers the whole group 10 apart only when there's no gap or the group still holds unranked items. That way the usual placement writes one record, and serve's change cloud stays on the new item.
- rank is the strict op (ed34): every listed ID must be open work in the group, every open item in the group must be listed, and it then renumbers 10, 20, 30 and writes only the items whose rank changed.

What I rejected:
- Renumbering on every placement: simpler, but it rewrites the whole group each time and clouds everything in serve.
- A `set <id> rank` field: agents would be writing numbers, which the plan rules out.
- Accepting a partial list in mull rank: ed34 settles that.

Captured items never get a rank, and --before/--after on a capture is refused.

The CLI adds mull rank (a write, so it's a batch op too) and add --before/--after. shapes_test now checks rank on items and the rank result's shape against mull guide json. Tests are in rank_test.go: appending per group, midpoints and renumbering, the strict refusals, unranked items ranked on first placement, and joining a group by commit, start, set phase and unfiling.
