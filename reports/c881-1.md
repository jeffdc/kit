# Done report 1: If things in a project need my attention I have no idea how to find them: the UI only marks blocking work. We have the special blocking chrome; we need something that highlights when my attention is needed even if it's not blocking (c881)

## What was built

### Summary

Everything that needs you is now marked wherever you look, not only blocking work. The tree API counts open questions, reviews and decisions (parked ones aside) for each project, plan and phase. In the sheet index, the yellow stamp still marks blocking work, and a new ink box counts the rest: '3 FOR YOU' on a project, a bare count on a plan or phase row. So kit shows 3 for you, forage-rework 2 and mull serve 1 (decision 1545), where before kit showed nothing. A project's title block now has a Needs you field (count, any blocking, and '2 questions · 1 decision') in place of Agents working, which the Plans column already lists. All projects has one Needs you column, with what it is, and a Needs you total; decisions weren't counted there before. A closed Needs you tier boxes its count so it can't be missed. DESIGN.md records the mark.

### UI tour

1. Run make build && ./mull serve and open http://localhost:6855/.
2. In the sheet index, each project row shows a yellow 'N BLOCKING' when work is blocked and an ink-outlined 'N FOR YOU' when anything else needs you; kit shows 3 FOR YOU.
3. Expand kit: forage-rework shows 2 (its two questions) and mull serve 1 (decision 1545). Hover a box for what it counts.
4. Open kit: the title block's Needs you field says 3 · 2 questions · 1 decision. The closed tiers 05 and 06 show their counts boxed.
5. On All projects: the Needs you column has each project's count with what it is, and the title block totals it.
6. Approve or answer something (e.g. mull accept 1545): the marks drop within a second.

## How it was built

### Design notes

Server: TreePage gains NeedsYou on the tree, each TreePlan and each TreePhase, counted with openEntries (the same filter Needs you uses: open, parked aside, retired kinds skipped) for all entries, the plan's (e.Plan), and the phase's items (entryPhase). The overview and project list already had the totals in summary.needs_you. The test checks each count equals the matching page's NeedsYou.Open and that a plan's count exceeds its blocking when it holds other entries. Documented in mull guide json.

UI: one helper, marks(blocking, total, long) in html.js, draws the yellow stamp (blocking only) and the new ink box ('.ask': the stamp's face in a 1px ink inset box, no fill) for the rest, shown only when total > blocking so a fully blocked row isn't marked twice. The tree uses it for project rows (spelled out, from the list summary, so it shows before the tree loads), plan and phase rows (bare counts, with a title). The project title block's Agents field becomes Needs you; All projects drops the Reviews and Questions columns for one Needs you cell (box plus breakdown) and its Waiting for review field for the total; the phone layout ends the row on Needs you (nl). A closed tier's count is boxed in ink by CSS (:not([open])), so a collapsed tier still says how much is inside.

Why ink: the contract gives yellow to blocking only and DESIGN.md's One Mark, One Job rule says a new state takes ink or a line before a hue; a boxed count reads as 'something here for you' next to the stamp without competing with it.

Rejected: a second hue (contract); counting captured bugs and ideas (they don't need the human until triage, by the model's rules); a separate attention list page (the overview's Needs you is that list; the gap was finding it).

Checked in Brave on kit, gallformers and the fixture, light and dark, no console errors.
