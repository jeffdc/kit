### Summary

## How it was built

### Design notes

One sort, workOrder in internal/mull/rank.go, is applied wherever the CLI lists items (ItemList for list and ready, Context, planView for show plan and plan show, Show for a phase, and the board's items before in_flight is built). Group keys: Unplanned last, then plan slug, then the phase's position from phaseOrder (unfinished phases by depth of unfinished needs then age, matching the schedule's steps; done phases after), unfiled items after the plan's phases; within a group openWork first, then rankLess (ranked before unranked, rank, oldest first). Sorting by rankLess for the non-open tail puts done and dropped (which keep ranks) before captured (rank 0), which matches 'unranked last'.

The start warning uses rankedAhead: open work in the group with a nonzero rank strictly below the item's. Strictly below and nonzero means equal ranks and unranked legacy items, which carry no stated order, never warn. A captured item started now is skipped, since place() just put it last and nobody chose that order. One warning line names all of them with their stage so an agent can judge (for example, work ahead that's only in review).

Rejected: ordering the view's phases or plan show's phases by schedule too (design.md settles the board's readiness order, and the item is about item lists); caching phaseOrder on state (a lazy cache could go stale inside an update transaction). Cost: make bench on the large seeded repo shows board (mull view) at 29.1 ms on main and 31.4 ms here, from computing phaseOrder per plan board; every serve page is unchanged since serve doesn't use these functions. Tests: TestListsFollowRank (list, ready, context, show phase and plan, ready after the first phase finishes), TestBoardInFlightFollowsRank, TestStartWarnsAheadOfRank.
