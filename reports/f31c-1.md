## What was built

### Summary

mull serve now draws every sheet the shell stubbed out, on the real API. A plan has three tabs (routes): Status (Where we are: phases in schedule order with done ones folded, state, cell bars, questions and needs; Needs you for the plan; What's next: each startable phase's work in flight and first ready items), Plan doc (markdown via a vendored marked 16.1.1, ID refs as status links, a status margin per section) and Backlog. The phase sheet shows its items, captures, Needs you and doc. The item sheet shows stage, claim, source and git, copyable actions for a captured item, its Needs you, the review packet (summary, tour, checks, report and commits; design notes, decisions with their settlement, files by layer) and its notes. A project's Unplanned and Backlog tabs are drawn, the backlog filterable by kind, triage, plan and category. Changed rows, titles, tabs and docs are clouded; every sheet refreshes live. Light and dark, down to phone width.

### UI tour

1. Run make build && ./mull serve and open http://localhost:6855/.
2. Open a plan from the sheet index (kit → mull serve). Status: Where we are lists phases by step (Can start now in blue, Then, Go live); open the Done row to unfold built phases. Below: Needs you for this plan and What's next.
3. Click Plan doc: the doc as formatted markdown; any phase or item ID in it is a link with its state, and the margin beside each section lists their status.
4. Click the plan's Backlog tab: what's captured for this plan, filterable.
5. Click a phase (a row, or the sheet index): its state, items, needed-by, what's captured for it, Needs you and its doc.
6. Click e3f5 under UI: the review packet. What was built (summary, tour, passed check, report and commits) beside How it was built (design notes, 9 decisions marked approved, files by layer), then Notes.
7. Open the project's Backlog tab: press Bugs, pick a plan (or No plan) and a category; rows filter; Clear filters brings them back. Click a captured item: Start it now, Commit to a plan and Drop each copy their mull command.
8. Open Unplanned: committed items with no plan.
9. With a plan open, run a write in that repo (e.g. mull ask "test?" --item <id>): the new question and the changed rows are clouded in red within a second, without reloading.

## How it was built

### Design notes

Shape: one module per sheet, beside the shell's. plan.js (planSheet with the title block and tabs, then planStatus, planDoc, planBacklog), phase.js, item.js (with the review packet), lists.js (the shared item table built from column definitions, Unplanned, and the Backlog with filters), doc.js (markdown). pages.js dispatches a project route to its sheet through projectSheet and names the API pages each route reads (subsFor). Every value from the API goes through esc; markdown goes through marked with the overrides below.

Data: app.js now keeps, per project, a pages map from API sub-path ("" for the overview, "plans/<slug>", "backlog?plan=<slug>", "phases/<id>", "items/<id>", "unplanned", "backlog") to {value} or {error}. Loading a project fetches its tree, its revision and the current route's pages together, and keeps only those pages, so a sheet not on screen is fetched again when opened and nothing stale is ever drawn after a change. Navigating to a sheet whose pages aren't loaded loads the project (coalesced as before). A 404 for a whole sheet becomes the Not found sheet with the API's message.

Markdown: marked 16.1.1, vendored from the locally installed package (no download), unchanged but for its source-map comment; licence and an update note beside it. A fresh Marked instance per render with: raw HTML escaped (blocks as paragraphs), links kept only for http(s), mailto and #, other targets shown as dotted text with the target as a tooltip, images as their alt text. An inline extension turns a 4-hex word into a ref link only if the API's doc_refs lists it, so years and words stay plain. renderDoc lexes once, splits the tokens at headings down to ###, and parses each section beside a margin of the refs it names (DocRef status, cells, questions). Checked with a hostile fixture doc: no script or img reaches the DOM, no dialog fires, javascript: and file links are demoted, tables, code blocks and quotes render.

Clouds follow the shell's matchers: phase rows by within.phase, item rows and What's next rows by within.item, titles by their own record, the Plan doc tab and title-block field by a plan_doc change, the phase doc heading by a phase_doc change. Doc changes are whole-doc because a Change doesn't say which section moved (idea captured).

Folded rows: the plan's Done group is a <details data-rows> in a group header row; the rows carry data-group and app.js shows or hides them on toggle and after each render, keeping the open state like the tiers.

Rejected: a hand-written markdown renderer (18bb decided marked); fetching each plan's backlog with the project's (only the plan Backlog tab needs it); putting filters in the URL (backlogs are small and filters are a glance).

Verified in Brave (headless, puppeteer) against a scratch mull serve on kit, gallformers and a fixture repo: every sheet in light and dark at 1440 and 400 px without console errors; backlog filters, Clear filters, the Done fold, a missing item's Not found; live clouds on a plan sheet after a start and an ask.

### Decisions made in the session

Accepting the review ratifies these. To decide one differently, before accepting: `mull decide <id> "..."`

- **34e5** Each route reads its own API pages (overview, plans/<slug>, backlog?plan=<slug>, phases/<id>, items/<id>, unplanned, backlog); a project load keeps only the current route's pages, so any other sheet is fetched again when opened
  Why: An event refetches what's on screen; dropping the rest means no sheet ever shows data from before a change
- **5848** The review packet shows Accept and Send it back only while its review entry is open; once settled it shows the settlement, and each carried decision shows approved or its settlement, with Decide differently only while open
  Why: Read-first: buttons copy the mull command, and a settled review has nothing left to do
- **70c5** Backlog filters (kind, untriaged, plan, category) run in the page over the whole list and are kept per backlog while the page is open, not in the URL or storage
  Why: Backlogs are small; the API's ?plan= is used only for a plan's own Backlog tab
- **b824** A plan's Where we are table folds done phases into one collapsed Done row, then one group per schedule step; What's next shows each startable phase's work in flight plus its first two ready items and a count of the rest
  Why: As the prototype's Built before mull group and next block, on the API's schedule and next lists
- **d202** A changed plan or phase doc is clouded as a whole: the Plan doc tab and the title block's Plan doc field, the phase doc heading
  Why: A revision Change says the doc changed, not which section; the prototype's paragraph clouds need more from the API
- **d617** Plan tabs are routes: #/<project>/plans/<slug> (Status), /doc and /backlog
  Why: Extends the shell's hash routes; a tab can be linked and survives a reload
- **ee2f** Docs render through the vendored marked with raw HTML shown as text; only http(s), mailto and # links stay links, other targets (file paths, javascript:) become dotted text with the target as a tooltip, and images become their alt text
  Why: Docs are written by agents and the page can POST to mull serve; nothing in a doc should run or navigate somewhere unexpected
- **ee94** A 4-hex word in a doc becomes a status link only when the API lists it in doc_refs; each section (split at headings down to ###) gets a margin with the status of the phases and items it names
  Why: Keeps years like 2026 and words like 'beef' plain, and uses the server's own reading of which IDs a doc names
