## How it was built

### Design notes

The change is one branch in the view's problem pass (internal/mull/view.go, PlanBoard's in-review/done case). The condition is unchanged: seen_in_git is false, meaning none of the item's linked commits (trailers or a merge of its id-branch) is on its plan's target. What changed is the timing: for StateDone the problem is raised at once, with its own text ("accepted, but none of its work is on <target>"), while StateInReview still waits notInGitAfter (three days since the item was last updated) and keeps its old text. No new git reads: the same ItemGit is used, so the view's cost is unchanged.

Rejected: also flagging a done item that has some commits on the target and others still unmerged (Unmerged > 0). Squash, rebase and cherry-pick merges leave the original branch's commits unreachable from the target until that branch is deleted, so this would flag merged work; and commits written after acceptance are already their own problem (work-after-accept). Rejected: a new problem kind (accepted-not-in-target). It is the same condition, nothing on the target, so one kind keeps view, serve and json consumers unchanged; only the wait depends on the state.

Docs: design.md's Problems row, json.md's done-not-in-git description, and supervisor.md gains a done-not-in-git bullet under PROBLEMS (the supervisor is who merges, and the problem now fires right after accept). The agents guide and kit's AGENTS.md copy are unaffected.

Test: TestAcceptedNotInTarget (target_test.go) sets a plan target, accepts one item whose work is only on main (flagged at once with the new text) and one merged into the target (not flagged), leaves one in review unmerged (flagged only after three days) and one in review merged (never flagged).

make bench, before (main's view.go) and after, medians in ms in-process, git calls unchanged everywhere: this repo board 24.2 -> 22.8, plan supervised-work 24.2 -> 22.8, overview 38.7 -> 35.3; large seed board 40.7 -> 39.6, overview 52.0 -> 46.9, plan metrics-23 34.0 -> 30.7.
