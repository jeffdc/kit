# Done report 1: mull serve's LaunchAgent runs as ProcessType Background, so macOS throttles its CPU and I/O (and its git children): pages are 3-5x slower than the same code run in the foreground (fa47)

**Status:** PASSED  
**Commit:** 5e3cd7b2a8bd

## What was built

### Summary

mull serve's LaunchAgent now asks for ProcessType Interactive instead of Background. Background throttled the server's CPU and I/O and its git children's, making every page 3-4x slower than the same code in the foreground (make bench on kit: tree 65ms over HTTP in-process vs 258ms from the installed server; mull view 0.17s vs 0.52s under taskpolicy -b). Takes effect when the agent is reinstalled.

### UI tour

1. Run make install in mull/ (it reinstalls the LaunchAgent, restarting mull serve on the new binary).
2. plutil -p ~/Library/LaunchAgents/mull.serve.plist shows ProcessType => Interactive.
3. make bench BENCH_FLAGS="-n 3 -url http://127.0.0.1:6855": the live column for kit is now close to the http column, not 3-4x it.

### Checks (run by mull)

- `make done-checks`: pass, 19.9s

## How it was built

### Design notes

A one-line change in internal/launchagent's plist builder, with a comment saying why, and the plist test now asserts the value.

I chose Interactive over removing the key: launchd.plist(5) says an unset ProcessType (Standard) still gets light CPU and I/O limits, while Interactive gets the same limits as an app, which is none. mull serve is idle almost all the time and only works while the human is looking at a page, so app priority costs nothing when idle. Adaptive was rejected: it moves between Background and Interactive by XPC activity, and mull serve speaks HTTP, not XPC.

I confirmed the cause without touching the installed server: mull view under taskpolicy -b (the same darwin background policy) takes 0.52s against 0.17s normally, matching the 3-4x gap make bench measured between the in-process handler and the live server. The live number after the change needs the agent reinstalled, which restarts the human's server, so it's in the tour rather than done here.
