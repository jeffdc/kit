It refuses a go run build and anything off macOS, warns when the port is taken, and reports launchctl failures as launchd_error. ## How it was built

### Design notes

LaunchAgent: a small package, internal/launchagent. Agent{Home, UID, Exe, Port, Env, Launchctl} builds the property list (Label mull.serve; ProgramArguments the binary, serve, --port N; EnvironmentVariables; RunAtLoad; KeepAlive; ThrottleInterval 30 so a taken port doesn't spin; ProcessType Background; stdout and stderr to the log) with escaped XML, writes it, then runs launchctl bootout gui/<uid>/mull.serve (ignored when not loaded) and bootstrap gui/<uid> <plist>, retried up to four times with growing pauses because launchd can refuse a bootstrap right after a bootout. Uninstall boots it out and removes the plist, reporting whether one was there. launchctl is injected, so the tests run a fake and never touch the machine's launchd; they check the call sequence, the retry and give-up, the plist's content, and lint it with plutil when present.

The command: mull serve --install / --uninstall (with --port), refusing both together (usage), off darwin (not_allowed: run it under your own service manager) and from a go run build (not_allowed: install mull first). The binary path is resolved through symlinks. PATH and XDG_CONFIG_HOME are captured as they are now, so the agent finds git and the same registry. A port already in use is a warning in the output, since it's usually the human's own mull serve, which the agent replaces once stopped. launchctl failures map to a new error code, launchd_error, documented in mull guide json with both outputs.

Docs: README and CLAUDE.md edited directly. design.md was brought up to Model v2 by a subagent working from the CLI's help, mull guide json and the code, then reviewed here: the data model table, stages, the backlog replacing Ideas, the inbox without loose ends, done and review ending in done, the current view --text, the CLI table, the protocol, intake, a mull serve section (with the marks and Not on mull yet added in review), and Transition and Build order kept as history.
