## How it was built

### Design notes

Root cause: nothing was lost. BacklogPage (internal/mull/pages.go) sorted untriaged first, then by category, and itemRows' order (oldest first) broke ties. With every kit item untriaged, uncategorized items came first oldest-first, so a fresh capture (no category) landed at the end of that block, mid-list, while the bottom row was the newest categorized item (1024). Jeff looked at the bottom and didn't see his captures.

Fix: sort by Created descending, then untriaged ahead of triaged. Category no longer orders the list; the Category filter still narrows it. Done in the server, so the plan's Backlog tab and the project's agree. TestBacklogNewestFirst pins the order with a category and a triage tie.

Toast: the capture toast now links the ID (href.item) and 'backlog' (the project's, or the plan's /backlog tab when tagged). A toast lasted 5s with no way to click it, so it now holds while hovered and restarts its 5s on leave; links are underlined in Bond on ink. DESIGN.md's Routes, Capture and Toast lines say so.

Rejected: highlighting the new row on arrival (the change cloud already exists for agents' writes, and the human's own writes are acknowledged as seen); keeping category grouping with newest-first inside each group (that still buries a new uncategorized capture below nothing only by luck).
