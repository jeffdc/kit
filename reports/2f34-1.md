## Summary

mull done now requires design notes (--design, how it was built and why; empty or none fails with design_required), and the review it files carries the item's open decisions: accepting the review ratifies those still unsettled, mull decide on one beforehand overrides it, and sending the review back leaves them open for the next done. The report renders what (summary, tour, checks) and how (design notes, decisions, changes by layer). Guides, AGENTS.md, json.md and design.md updated; documented form is mull done <id> --summary ... --tour ... --design -. DESIGN NOTES: Report gains design and decisions ({id,text,detail} snapshot at done); Entry gains decisions (ids, reviews only), set in the same done transaction from state.openDecisions (unsettled, not parked, item match). accept settles carried decisions through a small acceptCarried helper using the existing settle path (note 'with review <id>', same on-request), skipping any already settled or named explicitly in the same accept, so batch and accept-by-item work unchanged and there is no new command for overriding. Design is validated up front next to the summary, with its own error code like tour_required; --override does not waive it. The CLI allows only one stdin flag among summary, tour and design. view.go untouched to keep merges small; double counting in needs_you filed as bug 8523.

## UI tour

1. No UI changed; this is a CLI walk-through. Build with: cd mull && go build -o /tmp/m . and use a throwaway repo (git init, one empty commit, /tmp/m init, /tmp/m plan new demo Demo, /tmp/m config checks true)
2. Add and start an item, then record two decisions on it: /tmp/m decided "Store raw payloads" --item <id> --detail "replay later" (and a second one)
3. Commit a file with the trailer Mull: <id>, then run /tmp/m done <id> --summary "x" --tour none and see it refused with code design_required (same for --design none)
4. Run printf 'How it was built.\n' | /tmp/m done <id> --summary "x" --tour none --design - and see review_entry printed; passing --tour - and --design - together fails with code usage
5. Run /tmp/m report <id> --text and see two parts: What was built (Summary, UI tour, Checks) and How it was built (Design notes, Decisions made in the session with each id, text and why, Changes by layer)
6. Run /tmp/m inbox --text and see the review row end with [carries decisions <ids>]; /tmp/m show <review-id> has a decisions list
7. Run /tmp/m decide <one decision> "Something else" --on-request, then /tmp/m accept <item> --on-request: entries lists the review plus the other decision (settled note "with review <id>"), and /tmp/m decisions shows the overridden one with your text
8. Optional: send a review back with /tmp/m do <review> --reason "..." and see its decisions stay open; start and done again and the new review carries them
