# Done report 1: A copy-the-ID button beside every ID in mull serve (a622)

**Status:** PASSED

## What was built

### Summary

Every item, entry and phase ID in mull serve now has a small copy-ID button beside it: one click (or Enter or Space) copies the bare ID, the icon ticks in place for a moment, and the toast says "Copied the ID a622." It's one element, copyId() in html.js (copyButton() alone in the sheet index), used in item tables (Unplanned, Backlog, a plan's or phase's items), the phase table and its Needs column, item and phase title blocks (always shown there), Needs you rows and their 'on' links, decision groups and rows, the review packet's decisions and its ratify note, the revision schedule, the Plans column's agents, What's next, doc status margins, Find's hits and the sheet index's item rows. It stays transparent until its row is hovered or focused, and always shows on touch screens. DESIGN.md has a new Copy the ID section, and TestIDsCopy fails if a module draws a record ID without copyId. A plan's slug has no field to copy from yet (captured as a03f).

### UI tour

1. Open a project's overview: Needs you rows look as before. Hover a row: a small two-squares icon appears beside its ID (and beside the 'on <item>' link).
2. Click the icon: it turns to a tick for a moment, the toast says "Copied the ID …", and the page doesn't navigate. Paste somewhere: just the ID.
3. Open an item's sheet: the ID field in the title block always shows the icon. Click Answer or Decide differently, type a few words, then copy a decision's ID from the review packet: the form stays open with your draft.
4. Open the Backlog: hover a row and the icon shows in the ID column; click the ID text itself and the row still opens the item.
5. Press Tab through a table: the copy button is a stop beside each ID and shows while focused; Enter copies.
6. Expand the sheet index down to items and hover an item row: the icon appears before the row's meta; click it to copy without leaving the sheet.
7. Press s and search for an ID or a title: each hit shows its ID with the icon beside it on hover; copying keeps Find open, and clicking the ID or the row opens the record.
8. On a phone or touch screen the icons always show, at 24px.

## How it was built

### Design notes

One helper, so every placement looks and behaves the same and the merge with a0e3 and eda9 stays small: copyId(id, html) in html.js returns the ID's markup (its <code> by default, or a link around it) inside a span.cid with a button.cp[data-copy-id] after it. copyButton(id) is the button alone, for the sheet index, where the ID sits inside the row's link. Each call site changed only the expression that drew the ID, plus its import line.

The button is outside any link (a button in a link isn't valid HTML, and it would hijack the link): the link still opens the record, a click on a table row's ID text still opens the row, and the button holds no text, so selecting or double-clicking the ID selects just the ID. In Find, the hit was one link holding the ID, so the ID became its own link (tabindex -1, same href and data-hit) in the row's first grid column, with the button beside it; the row's link holds the title and stage. The list item now carries the grid, hover and selected fills.

It's a copy action (Two Kinds of Action Rule): app.js's click handler takes [data-copy-id] first, before writes and before the click-elsewhere disarm, and reuses copy(), which now reports whether the clipboard took it. On success the button gets .ok for 1.6s (the icon swaps to a tick by CSS; both paths are in one SVG) and the toast says "Copied the ID <id>." — the toast is role=status, so it's also what a screen reader hears. On failure the ID's text is selected for ⌘C and the toast says so. Handling it first means an open text form keeps its draft and stays open, so an ID can be copied into an answer. data-copy-id joined focusKey, so focus comes back after a live re-render.

Quiet in dense places: where the pointer hovers, .cp is opacity 0 until a containing row (tr, .it, .grp li, .grp > summary, .decn, .node, .ag, .co, .find li, .rv-note) or the .cid itself is hovered or has focus-within. Opacity rather than display or visibility keeps its room (nothing reflows on hover) and keeps it in the tab order, so keyboard users reach it and it shows when focused. Title blocks always show it. In the sheet index, rows are too tight to keep 20px on every item row, so there it's width 0 (and its gap cancelled) until the row is hovered or focused; still focusable at width 0. On (hover: none) it's always shown, and on (pointer: coarse) it's 24px. The .ag grid's ID column went from 40px to 52px to fit the button.

Not covered on purpose: inline ID references in doc prose (the section margin lists them with buttons), hashes, branches and worktrees. Plan slugs only appear with a button in Find; showing a plan's slug on its sheet is captured as a03f, since plan.js is being changed by a0e3 and eda9.

TestIDsCopy scans web/*.js for <code>${esc(x.id)}</code> or x.item drawn without copyId on the same line, so IDs added later get the button too.

Checked in the dev UI (make dev on 6903) with headless Brave over CDP: buttons present on the overview, backlog, item, plan and review pages, none inside a link; hidden until hover and shown on hover or keyboard focus; click and Enter copy the bare ID (read back from the clipboard) without navigating; the tick clears after 1.6s; an open form keeps its draft; the sheet index's button takes 0px idle and 18px on hover; Find copies and stays open, and its ID link still opens the record; the phase table, its Needs column and doc margins rendered by the real modules on synthetic data (the demo has no phases); at 400px with touch emulation the buttons show at 24px with no horizontal overflow.

### Decisions made in the session

Accepting the review ratifies these. To decide one differently, before accepting: `mull decide <id> "..."`

- **98b3** The copy-ID button confirms twice: its icon turns to a tick for 1.6s where it was clicked, and the toast says 'Copied the ID <id>.'
  Why: The tick is the in-place confirmation Jeff asked for; the toast keeps the established copy vocabulary (every copy says so in the toast) and is the role=status region, so a screen reader hears it. Neither says 'a prompt for an agent'.
- **6d8b** The button sits beside the ID, outside any link (copyId wraps the ID's markup, link included), so the link still opens the record and the ID's text selects on its own
  Why: A button inside a link isn't valid HTML. In Find the ID becomes its own link (out of the tab order) so its button can sit beside it; in the sheet index it sits after the row's link, before the meta.
- **7dc3** Inline ID references in doc prose get no button; the section's status margin lists each ID it names with its button
  Why: A button inside a sentence breaks reading, and the margin already lists every ID the section names.
- **a6b5** Copying an ID is handled before anything else on a click, so an open text form keeps its draft and stays open (ready for the ID to be pasted in)
- **b52e** Quiet by opacity, not display: the button is transparent until its row or the ID is hovered or focused, keeping its room and its place in the tab order; always shown in title blocks and on touch screens (24px there); in the sheet index it takes no room until its row is hovered or focused
  Why: Opacity means nothing moves on hover in dense tables and Tab still reaches it; the sheet index's rows are too tight to keep 20px for it on every item row.
- **5a4d** A test (TestIDsCopy) fails when a web module draws a record ID (<code>${esc(x.id)}</code> or x.item) without copyId
  Why: So IDs added by later work (a0e3, eda9 and on) get the button too.
