## How it was built

### Design notes

Since report 1 (the LaunchAgent and the docs), sent back to fold in picking up new builds; two changes.

Restart on install: the Makefile's install target, after go install, checks for ~/Library/LaunchAgents/mull.serve.plist and if it's there runs the just-installed binary (GOBIN, else GOPATH/bin) with serve --install. That rewrites the plist for the new binary and boots the old process out before bootstrapping the new one, so the port is free. Nothing happens when the agent isn't installed. Checked with make -n; not run for real here, since it would install over the human's binary and load their agent.

Reload on a new build: a new option, WithBuild(version), serves GET /api/build with {build, version}. build is the first 12 hex of SHA-256 over the version and every embedded web file, so it changes with the version and with any UI change, including a dirty build that keeps its version. cmd/serve passes cmd.Version. The page fetches it at start; when the event stream reopens (which a restart always causes), it fetches it again and reloads the page if it differs, else refetches the data as before. A server without the endpoint is tolerated. Tested: TestBuild (absent without the option, stable per version, different across versions); end to end in Brave against two binaries built with different versions: restarting on the same build left the page alone, restarting on the other made it reload, on the same route, and come back Live.

Rejected: polling for a new build (the reconnect is the moment a new build can appear); reloading on every reconnect (a dropped connection or a restart of the same build shouldn't lose the page's state); watching the binary from inside mull serve (the LaunchAgent restart already covers it).
