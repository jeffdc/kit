## What was built

### Summary

Commands no longer register a repository whose main worktree is in the system's temporary directory ($TMPDIR, /tmp, /private/tmp, /var/folders, matched as given and with symlinks resolved), so agents' scratch repos and tests' repos stay out of Jeff's mull serve without anyone having to remember. Explicit registration (registry.Add) is unaffected. New `mull unregister [<path>]` (default: this repo) takes a repository off ~/.config/mull/repos and prints {path, registry, removed}. It replaces the file atomically, so mull serve drops the repo at once, and the command doesn't re-register the repo on its way out. Tests cover temp repos never registering (from the main worktree or a linked one), a normal repo still registering, unregister from a worktree, by relative path and for a stale line, and serve noticing the removal. Docs updated: design.md, mull guide json, docs/serve/README.md and serve's help.

## How it was built

### Design notes

Temp-dir rule. The check lives in registry.Register, the auto-registration every command runs after it finishes, and not in registry.Add, so explicit registration (serve's tests, a future register command) is unaffected. Register already resolved the main worktree; it now asks registry.Temporary(main) before adding. The roots are os.TempDir() (so $TMPDIR), /tmp, /private/tmp and /var/folders. Each comparison tries both the cleaned path and its symlink-resolved form against both forms of each root, because git reports /private/var/folders/... on macOS while $TMPDIR says /var/folders/..., and a root or path that doesn't exist can't be resolved at all; resolving only one side failed my first test. A root that is / or contains $HOME is dropped, so an odd TMPDIR can't silently stop every repository registering (decision bd20). No extra git calls: Register makes the same three as before, plus a few EvalSymlinks.

Testability. Every gittest repo lives under the system temp dir, so the rule would stop all registration in tests. registry.SetTempRoots(roots) swaps the root list and returns a restore func (tests use t.Cleanup(registry.SetTempRoots(nil))). It has to be exported because cmd's tests need it, and gittest can't own it (registry's in-package tests import gittest, so that would be an import cycle). I rejected an environment variable to switch the rule off, since agents could reach for it. Tests still run with gittest's isolated XDG_CONFIG_HOME, and cmd's TestMain keeps its own.

Unregister. registry.Remove(paths...) rewrites the file without every line naming one of the paths, keeping comments and blank lines. It writes a temp file in the config dir and renames it into place (as seen.json does), so the serve watcher, which watches the directory, sees one change to "repos" and resyncs (TestWatchRegistry now covers this). A concurrent Add between the read and the rename can be lost; the next command adds it again. The command `mull unregister [<path>]` (cmd/serve.go, beside serve) takes cwd or a path relative to it. If that path, as given or resolved, is itself a registry line, only that line goes (a deleted repo, a hand-added line), so a stale path inside another repo's tree can't take that repo off by mistake. Otherwise it unregisters the main worktree of the repository containing the path (decision b285). It prints {path, registry, removed}, with removed false when the path wasn't registered, like serve --uninstall (decision 88dc). Execute registers after every command, which would put the repo straight back, so the command sets app.unregistered and Execute skips Register for it. Unregistering doesn't stick: a later command in that repo re-registers it (decision 2407). I captured idea 5c22, a per-repo opt-out, for .dev/bench and .dev/demo, which aren't under the temp dir.

Dropping registered paths that no longer exist: worth doing, but not as an automatic delete. A repository on an unmounted volume, or one moved and about to move back, would vanish from the registry for good. serve already shows missing paths as not_a_repo errors, so a better shape is a "forget" action on that error row in serve (or `mull unregister --missing`) that Jeff triggers. Not done here.

Docs: docs/design.md (the registry), mull guide json (an unregister row in the commands table, and the registry paragraph under mull serve), docs/serve/README.md, and serve's help text. The agents guide and AGENTS.md are unchanged, since agents don't have to do anything differently. make bench wasn't run: no serve read path changed, and Register's git calls are the same.

### Decisions made in the session

Accepting the review ratifies these. To decide one differently, before accepting: `mull decide <id> "..."`

- **2407** Unregistering doesn't stick: any later mull command run in the repository registers it again (no exclusion list)
  Why: The item asked for removal only; temp repos are covered by the rule, and an exclusion list is more state for Jeff to manage
- **88dc** mull unregister prints {path, registry, removed}; removed is false (not an error) when the path wasn't registered, like serve --uninstall's removed
  Why: Idempotent, so a script or agent can run it without checking first
- **b285** unregister removes the path as given when it's in the registry as written (a deleted repo, a hand-added line); otherwise the main worktree of the repository containing it
  Why: So a stale line inside another repo's tree never takes that repo off by mistake
- **bd20** A temporary-directory root that is / or holds the home directory (an odd TMPDIR) is ignored
  Why: Otherwise a stray TMPDIR would silently stop every repository registering
