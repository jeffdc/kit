# Done report 1: A done (accepted) item keeps its claim: its sheet's Claim field and the item tables' meta line still read '<worktree> · <branch> · since …' as if an agent still held it (9d94)

## What was built

### Summary

An item's claim no longer looks live once the work is finished. On its sheet the Claim field shows 'since …' only while the item is active; in review, done or dropped it reads 'Worked in <worktree> <branch> · from <date>'. Item tables (Unplanned, phase lists) show the claim line only for active items. Nothing in the data changes.

### UI tour

1. make install, open any accepted item's sheet (e.g. d4e5 in kit): the title block's field reads 'Worked in kit d4e5-backlog-newest · from Nov 15' (or the branch it was claimed on), with no 'since'.
2. Open an item in review: the same 'Worked in' field.
3. Open an active item (when an agent has one): the field reads 'Claim' with '· since …' as before.
4. Open kit's Unplanned with 'Show them here too': finished rows have no worktree line under their titles; active ones still do.

## How it was built

### Design notes

The claim (worktree, branch, time, base commit) is set by mull start and cleared only by release or a send-back, so it survives into review and acceptance. That's deliberate in the data: the done report's changes are measured from claim.Base, and it records where the work happened. The problem was purely presentation: item.js's Claim field and lists.js's title column drew any claim as a live one ('since …').

Change, in the UI only: item.js gets claimField(it). Active: 'Claim', worktree, branch, 'since <ago>' as before. Any other stage with a claim (in review, done, dropped): 'Worked in', worktree, branch, 'from <day>'. No claim: 'Claim · none'. lists.js draws the claim meta line only for active items. The CLI needed nothing: mull view and mull context already show claims only for active work, and AgentRow (Plans column) lists only active items. DESIGN.md's Title block paragraph states the rule.

Rejected: clearing the claim on accept or drop (loses the done report's base and the record of where the work was done, and changes mull's data for a display issue); hiding the field entirely for finished items (the worktree and branch are useful when looking back at the work).

Checked in headless Chromium against make dev after starting one demo item: the active item's field reads 'Claim: demo main · since just now', an in-review and a done item read 'Worked in: demo main · from Nov 15', and Unplanned (all) shows a claim line only on the active row.
