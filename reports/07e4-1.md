## How it was built

### Design notes

How: three layers, each small.

seen: Look gains Acked []Ack {type, id, commit}. Acknowledge(repo, acks) merges into the existing look (a later ack of the same record replaces the earlier one) and does nothing for a repo with no look, since its baseline will take everything in anyway. Mark replaces the look, so marking seen clears the list without special code.

mull: Change.Ref() and RecordRef name a record as a change does; Ack pairs one with the acting commit. Wrote(commit) is recordChanges(commit^1, commit): exactly what that write changed (the first commit wrote none). Acknowledge(rev, acks) computes, once per distinct ack commit, the records changed between it and the tip, and drops a change from rev when its record is acked and not among those; acks naming commits off the branch are ignored. It reuses recordChanges, so "changed again" has the same meaning as everywhere else in revisions.

serve: revisionSince (used by GET revision and the project list's count) applies the acks after the baseline logic, which I flattened so the acks of whichever look is in effect are used. POST …/ops, after a write, acks Wrote(commit) with that commit and returns them as acknowledged; a failure there is ack_error on a 200, since the write stands.

Tests: seen (merge, replace, no-look, Mark clears), mull (Wrote for a review accept and the root; Acknowledge hides, re-clouds after a later change, ignores off-branch acks), serve (approve through the endpoint: only the other change stays clouded, in the revision and the project list's count; marking seen clears the list). Existing tests that compared Look with != now use reflect.DeepEqual, as Look holds a slice.

### Decisions made in the session

Accepting the review ratifies these. To decide one differently, before accepting: `mull decide <id> "..."`

- **0c34** Mark revision seen clears the acked list; a mark made with an older commit than an ack can cloud that record again
  Why: Clearing keeps seen.json small and needs no git in package seen. The race (marking between a write and the redraw) only over-clouds, never hides.
- **64cb** A write acknowledges every record its commit changed (the diff from its first parent), not only the records its ops name
  Why: Accepting a review also changes its item and carried decisions; all of it is the human's doing. A record only named (e.g. the plan an item goes to) isn't acknowledged, since it didn't change.
- **86fb** An acknowledged record is clouded again, with its whole change since the last look, as soon as it changes after the acting commit
  Why: Whatever changed after the human acted is news; showing the full change since the last look is simpler and never hides anything.
- **c470** If recording the acks fails after a write, POST …/ops still answers 200 with ack_error, and those records stay clouded
  Why: The write has happened; an error status would tell the page it didn't.
