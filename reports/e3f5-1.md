## How it was built

### Design notes

Shape: flat ES modules in internal/serve/web, no build step. app.js holds state, loading, routing and actions; api.js the fetch calls and the EventSource; html.js escaping, links, tags, cell bars and times; tree.js the sheet index; title.js the title block and tabs; needs.js the Needs you schedule; plans.js the Plans column; revision.js the change matchers (Changes), the revision schedule and how a change is described; pages.js the sheets. Every sheet is a function from state to an HTML string, with every API value through esc. The CSS is the prototype's shell CSS, ported as is (two mangled cloud selectors fixed), minus the doc, review packet, filters and model page that f31c needs.

Data: GET /api/projects for the list, then tree + revision for every readable project (the tree and the home sheet's now lines need them) and the overview only for the project on screen; other projects' overviews are marked stale and fetched on navigation. Loads are coalesced per key: one in flight, at most one queued, so an event burst is two fetches. An SSE project event refetches the list and that project; a reopened stream refetches everything (events aren't replayed). The list's revision count is overwritten from each revision fetch so the title block, the home rows and the tree agree.

Clouds: Changes wraps one project's revision changes, with matchers (within.item, phase, plan, unplanned, backlog, entry). The tree uses one recursive rule: a collapsed row is clouded if anything inside it changed; an open one only for changes none of its children match. Runs of clouded rows share a cloud, broken at project boundaries so Mark revision seen can fade one project's. A closed tier shows a cloud at its header via :has(.cl). Changes not present in the previous revision fetch are fresh and draw in; fresh lasts 750 ms because an event re-renders twice. Mark revision seen fades the clouds, then posts the commit the page showed, so anything newer stays clouded.

Live re-render replaces main and the tree wholesale (cheap at this size); what the human opened (tiers, groups, the revision schedule) is remembered by data-open key and reapplied, and keyboard focus is restored to the matching control. Relative times tick every 30 s without a re-render.

Rejected: real paths with the History API (the file server would 404 deep links without a server change); a DOM-diffing library (no build step, and string rendering is enough at this size); loading Google Fonts in the meantime (a local tool shouldn't call out; 0114 self-hosts); per-row change counts on the home sheet (the contract: the cloud alone means changed).

Verified in Brave (headless, puppeteer) against mull serve with a scratch XDG_CONFIG_HOME registering kit, gallformers, an uninitialised repo and a scratch fixture repo: home, overview, stubs, not found and unreadable sheets at 1440, 900 and 400 px, light and dark, no console errors; live clouds after batch writes, Mark revision seen, focus and open tiers kept across an event, and stream drop and reconnect with a write made while down.
