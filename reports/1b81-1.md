## How it was built

### Design notes

A new state helper, agreedPlan (in mull.go, next to openPlan), returns a plan that can take phases and committed work: open and not shaping. It is the one place the rule lives and the one error message (invalid_state, naming mull plan agree <slug> --on-request).

Every path that creates committed work goes through it: phaseAdd; addItem when the stage isn't captured (captures still use openPlan, so backlog can be tagged to a shaping plan), which covers add, do and review follow-ups; and commit, which now checks the final plan after any retag rather than only when retagging, so a capture already tagged to a shaping plan can't be committed into it. commit computes the new plan and phase before touching the record.

start refuses a capture tagged to a shaping plan, because starting from captured commits it; committed work already sitting in a shaping plan (impossible now, and none exists in real data) keeps 5ea9's warning instead of becoming unstartable.

Tests: most tests now agree their plans through an agreedPlan test helper; batch tests insert a plan agree line (or use setup's agreed general plan where line numbers are asserted). The plan-state test was rewritten around the refusals.
