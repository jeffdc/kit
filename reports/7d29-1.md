## How it was built

### Design notes

Text only: no code path changes, so no mull guide json change and no bench.

Agents guide, step 2 (and kit's AGENTS.md copy, kept byte-identical): the branch line now says to make <id>-<short-name> from the tip of the item's plan's target (target.branch on its plan in mull context; integration for unplanned work), and to make it before mull start. That ordering matters because start records HEAD as claim.base and the current branch as claim.branch, and done measures the diff from claim.base; a branch made after start leaves both wrong. A new bullet covers the worker's own worktree: make one with git worktree add -b only if none was made for it (harnesses often make it), set it up as the plan's rules or the project's AGENTS.md say, and leave removal to the supervisor. It states plainly that mull never creates or removes worktrees (c6c0).

Supervisor guide: a Worktrees bullet under Handing out work says the same from the supervisor's side, and that missing setup steps go into the rules via mull ask, never into the hand-off (keeps the one-line hand-off rule intact). A new section, Removing worktrees, after Reviewing finished work: only once the item is done (accepted) and has no done-not-in-git problem; take the path and branch from the claim (mull show <id>, which keeps the claim on done items); run git worktree remove, then git branch -d (in that order, since git won't delete a branch checked out in a worktree), from a checkout of the target, since -d checks merged-ness against the upstream or the current branch. Both refuse when work would be lost, so a refusal is the signal to look, and forcing needs Jeff's word. I deliberately didn't mention mull worktrees: it's item 1499, not built yet; that item should add a pointer to it here.

design.md: the protocol outline's step 2 and the supervisor outline gain the same points, plus a short paragraph that worktrees are the guides' business, not mull's, and that project setup lives in rules or AGENTS.md rather than mull config.

Test: cmd_test's list of phrases each guide must keep now includes the target-tip branch rule and "mull never creates or removes worktrees" (agents), and "mull never creates or removes them", "git branch -d <id>-<short-name>" and "Never force either" (supervisor).

Rejected: putting removal under the end-of-session section (it's a per-item step after acceptance and merge, not a session ritual), and telling workers to remove their own worktree (they can't know the work reached the target, and the accept is not theirs).
