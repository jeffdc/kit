## How it was built

### Design notes

The failure came from three lines of the guide working together: "Notes are short. Don't copy long prose; link the document instead", the instruction to cite each matter, and "They stay readable in .mull/ either way". An agent following them faithfully writes a one-line summary plus a citation, which is what stejar (67 of 68 open records) and gallformers (51 of 62) got. The fix replaces the brevity rule with a sufficiency rule: carry what the work needs (specifics, decisions and reasons, done-when), in the matter's own words where they serve, taking only the relevant sections of a long hub matter, and leaving out status and history. Brevity was trying to keep status and history out of mull; that's kept, as the explicit exclusion.

Jeff's decision that .mull/ stays as an archive (files in the repo may refer to it) is stated in the opening rule and in section 6, which no longer calls deleting it a later decision.

The repair procedure lives in the guide rather than only in a prompt, so any agent in any harness gets it from `mull guide intake`, and Jeff's prompt can be short. It forbids re-planning (no changes to plans, phases, needs, titles, states or decisions) because the point is carrying content into records Jeff already approved. Inbox entries can't be edited with set, so the procedure files a replacement and names the old entry for Jeff to settle. The example batch had an item whose notes were only a citation, which taught the very habit being fixed; it now shows notes that carry the work, then the citation.
