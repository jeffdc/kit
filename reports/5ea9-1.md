## Summary

Plans now have Model v2 states: a new plan is shaping, mull plan agree <slug> --on-request (human only, also a batch op) makes it active, and plan close makes it done. A shaping plan can hold phases, items, captures and questions, but none of its items is ready and start warns. Done is stored as closed and translated at the model's YAML boundary like item stages, so existing active plans stay active. view lists shaping plans after active ones with a state on each board; context lists shaping and active plans with their state. json.md, design.md, README and the intake guide are updated.

## UI tour

1. No UI changed; the tour is CLI only. In a throwaway repo (git init, one commit), build ./mull from mull/ and run ./mull init.
2. /mull plan new launch "Public launch": prints the plan with state "shaping".
3. /mull phase add Billing --plan launch, then ./mull add Webhook --phase <phase-id>: the item has "ready": false, and ./mull ready is empty.
4. /mull view --text: the plan shows as "LAUNCH  Public launch  (shaping: not agreed yet)", listed after any active plans; ./mull context lists it with "state": "shaping".
5. /mull plan agree launch: fails with code not_allowed (only the human agrees a plan).
6. /mull plan agree launch --on-request: state becomes "active"; ./mull ready now lists the webhook item. Running it again fails with invalid_state.
7. echo '{"op": "plan agree", "slug": "launch", "on-request": true}' | ./mull batch --dry-run: the batch op exists (fails here with invalid_state since launch is already active).
8. /mull plan close launch: state "done"; ./mull view no longer shows it, ./mull view --plan launch does, and ./mull add x --plan launch fails with invalid_state.
9. /mull guide json: Plan state is shaping|active|done, plan agree is listed under commands and batch ops.
