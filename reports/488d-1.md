Records are self-describing, so mull reads both formats and writes only format 2: writes on unmigrated data (or migrated data holding format 1 records from sync) fail with migration_required; a newer format fails with unsupported_format. migrate --dry-run only reads and lists every change; the real run needs --on-request and is idempotent. It rewrites the format, captures open/parked loose ends and inbox ideas as captured ideas (entries settled do), converts phase needs on items to phase needs, drops item needs, and on the first migration retires general and turns summaries into doc stubs. ## How it was built

### Design notes

Format versioning. config.yml gains format (absent = 1; init writes 2). A repo-level flag alone isn't enough because sync merges per file: a machine on an older mull can add or change records after the migration, and a stored "done" means in-review in format 1 and done in format 2. So every record is self-describing: format 2 items keep their stage under a new key (stage:), format 1 under state:; phases live in phases/ vs epics/; a done plan is done vs closed; a settlement's phase is phase: vs epic:. The model's UnmarshalYAML reads both per record and marks format 1 records Legacy; marshalling has no translation any more (the stored-name maps on the write side are gone, the read-side LegacyStage stays).

Write gate. Mull.update (the single path for record writes, ops and batch included) now checks state.writable(): format < 2, or any Legacy record (or any file under epics/ or docs/epics/), fails with migration_required. Reads (view, context, show, list, docs) keep working. updateAny is the ungated path used by migrate itself and by the check cache (a cache, not a record). load() rejects format > 2 with unsupported_format, for reads too. view gains format and migration_required (and a MIGRATE text line); context prepends a protocol line while writes are refused.

Migration (internal/mull/migrate.go). It loads the state with the lenient reader, mutates the in-memory records, then writes back everything it touched through the normal put* functions (which write format 2), deletes epics/ and docs/epics/ paths, and records format 2. Each step notes its changes per record, so the result lists exactly what changes. Steps: formatChanges (raw re-read of each legacy item to report the stored value), retireGeneral (first migration only), captureLegacyEntries, convertPhaseNeeds (each conversion is tried against checkCycles with the needs still to come; a cycle means drop), dropItemNeeds, write (incl. doc moves and, first migration only, doc stubs and config). Steps that fix stragglers run every time; the ones tied to the 1->2 transition don't, which is what makes a rerun safe and a no-op on clean data. The dry run runs the same code in store.View, which never commits, so it can't write; the real run is one store.Update (one compare-and-swap). The real run needs --on-request, consistent with plan new / settling being the human's acts.

Phase doc history: History() uses --no-renames, so docLog now takes several paths (docs/phases then docs/epics), dedupes by commit (the move commit shows once, at the new path) and sorts newest first.

Tests: old-format fixtures are written directly with store.Init in throwaway repos (migrate_test.go, and TestMigrateShapes in cmd for the documented JSON keys): reads of format 1 data, every write refused without moving the branch, dry run leaves the head alone and reports counts/captures/needs, the real run is one commit on top of the old head with format 2 files and the same semantics, the moved doc's log keeps both versions, idempotence, stragglers from an "older mull" block writes and a rerun converts them without redoing stubs, general with phases is kept, newer format refused, set kind. Dry run on kit read the real branch and left it at the same commit.
