## What was built

### Summary

From mull serve Jeff can now edit, in place and saved as his own: an item's title and notes (captured and committed items alike, so the backlog is a place to write things down before an agent is involved), a plan's doc and a phase's doc. The ops endpoint offers set (for an item's title and notes only) and the existing plan doc and phase doc ops. Notes and docs get a roomy markdown editor that grows with its text; drafts are kept, and an edit can't silently overwrite text that changed under it.

### UI tour

1. Open a captured bug from the Backlog. Under its name click Edit title: the name becomes a one-line field with Save title off until you change something. Change it and press Enter: the toast says it's saved, the new name shows, and it isn't clouded.
2. In the Notes head click Write notes (Edit notes when there are some): the rendered notes give way to a large editor at the prose width. Type a few lines of markdown, press Esc: it closes, and the button now carries a small DRAFT label. Click it again: your draft is back.
3. Make the notes long: the editor grows with the text and the page scrolls; Save, Cancel and Discard changes stay stuck to the bottom of the window. Press Cmd-Enter: the notes render as markdown and the button reads Edit notes.
4. Open the editor again and type something, then change the same item's notes from a terminal (mull set <id> notes ...): the page redraws, your draft stays, and a line above the editor says it changed since you began this draft. Discard changes starts again from the new text.
5. Open a plan's Plan doc tab and click Edit the doc in its head; edit and save: the doc renders with your change and the tab isn't clouded.
6. Open a phase's sheet and click Edit the doc beside The phase doc; edit and save the same way.
7. Open a committed item, Edit title, clear the field: Save title goes off, so an item can't be left without a name.

## How it was built

### Design notes

Server. uiOps gains set, plan doc and phase doc. set is the op the item notes named for an item's title and notes, but it has no doc field for plans or phases (an item's set doc adds a doc path), so docs go through the plan doc and phase doc ops that already replace a doc. Because set can also retag, change kinds and rename plans and phases, offered() refuses set from the page unless its field is title or notes (uiSetFields), keeping the endpoint to what the UI offers. Nothing else changed on the server: the stale-page check already covers these ops (the item, plan or phase they name, and the doc file they write), and the write acknowledges what it touched, so edited text isn't clouded. TestOpsEditText covers a captured and a committed item, both docs, acknowledgement, every refused set field, and a stale edit refused while an unchanged record is still edited.

UI. editWrite in write.js sits beside textWrite and reuses its form, keys and save path, so it follows the Two Kinds of Action Rule as written (a .wr button opens a form in place; opening it is the asking once more; Save writes; Esc, Cancel or a click elsewhere closes it, keeping the draft). Edit adds to the state the text the draft began from (base) and the text as the page shows it now (value): Save stays off until the draft differs from value (and while a required title is empty); a draft that equals its base follows the text as it changes live; a touched draft whose base no longer matches shows a line saying the text changed, and Discard changes (a plain button: it saves nothing) starts again. A refused save (conflict) keeps the draft and base, so after the redraw the same line explains why. canSave is shared by the input handler and submit, so text writes behave as before (something written).

Placement follows "in place": the title's one-line form takes the h1's place in the title block (titleBlock takes an optional edit, the only change to title.js), and notes and docs put their button in the section head (.hd.ed) and the editor in place of the rendered text. Long editors are 15px Archivo at the 120ch prose measure, at least 16em, auto-grown in app.js (on render and on input) so the page scrolls rather than the box, which also keeps the cursor and scroll stable across live re-renders; their action row is sticky at the window's foot. render() keeps focus and caret for an input as it did for a textarea.

Tried with make dev on port 6901 in headless Chromium: title, notes, plan doc and phase doc saved and rendered, not clouded; the draft kept across Esc and reopening; the editor growing; a change under a draft shown and discarded; a stale save refused with the draft kept; an empty title not saveable; no sideways scroll at 390px. The dev demo now seeds a phase with a doc so phase sheets can be tried.

For the merge with eda9: model.js's "What you run" caption lists the writes; it should gain editing titles, notes and docs when eda9's rewrite of it lands. Captured: a bug that mull set accepts an empty title, a bug that running mull in the dev demo registers it in the real registry (it happened here: the demo under this worktree is in Jeff's ~/.config/mull/repos and seen.json, and there's no command to remove it), and an idea for a markdown preview.
