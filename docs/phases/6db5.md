The first edit the human sees, and the one that sets how every later edit looks.

- **Two kinds of action.** DESIGN.md's rule that nothing in the UI saves anything is replaced: copy actions stay as they are (copy, then say so in a toast); write actions look different, show a pending state while the write runs, and show a failure plainly where it happened. A conflict redraws the page and says why.
- **Approving.** A decision group's Approve all writes `accept` for its open decisions; each decision row gets its own approve. Approving is quick to do but can't be undone, so the confirmation is in place and light (the button asks once more), not a dialog.

Done when the human approves decisions from the Needs you schedule, they leave Needs you, and they aren't clouded as new.
