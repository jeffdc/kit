# Rank in the model and CLI

## Design

See the plan doc (`mull plan doc item-order`) for the shape agreed with Jeff; ed34 settles that `mull rank` is strict.

- **The field:** an item's `rank`, a sparse integer (10, 20, 30…), lower first, equal ranks mean no order between them. Absent means unranked (data from before this plan): it sorts after ranked items, oldest first. No migration.
- **The group:** a phase; a plan's items with no phase; or Unplanned. `mull rank <group> <id…>` names it by phase ID, plan slug, or `none`.
- **Writing it:** `mull rank` lists every open item in the group (committed, active, in review) in order and writes 10, 20, 30…; it refuses with the missing IDs otherwise, and refuses items not in the group. `mull add` ranks a new item after the group's last, and `--before <id>` / `--after <id>` place it (renumbering the group if there's no gap). An item moved into a group (`set <id> phase`, `commit --phase/--plan`, a captured item started into one) goes to its end. Agents never write numbers.
- **Reading it:** `ready`, `context`, `list`, `view` and `show <phase|plan>` list open items in rank order; across phases the ready list goes by the phase schedule, then rank. `mull start` warns, naming the item, when a lower-ranked open item in the group isn't done. Readiness is unchanged.
- **Docs:** `mull guide json` (the field, `rank`'s result and errors, the batch op), `mull guide agents` (reorder with `mull rank` when Jeff says what comes first), and `docs/design.md`'s Ordering section.

## Done when

An agent told "do X first" runs one `mull rank`, the next `mull ready` lists X first, and starting something ranked after X warns.
